# Django Admin – Enable Admin for Custom User Model (Register + Basic Customization)

## 🎯 Main Goal

Enable Django Admin support for a **custom User model** and make the users list page show the fields we want (email + name), so our admin test can pass.

---

## 📍 Where the work happens

Inside the **core app**, open:

`core/admin.py`

The instructor suggests clearing the file and rebuilding it cleanly.

Add a docstring at the top like:

- “Django admin customization”
    

---

## 📦 Key Imports

### 1) Import Django admin tools

```python
from django.contrib import admin
```

### 2) Import the default Django UserAdmin (as a base)

Django provides a built-in admin class for users. We reuse it and extend it.

```python
from django.contrib.auth.admin import UserAdmin as BaseUserAdmin
```

✅ It’s imported as `BaseUserAdmin` to avoid name conflicts with our custom `UserAdmin`.

### 3) Import your app models

```python
from core import models
```

This gives access to your custom user model (e.g. `models.User`).

---

## 🧩 Create a Custom Admin Class for Users

Define a `UserAdmin` class that inherits from the default `UserAdmin`:

```python
class UserAdmin(BaseUserAdmin):
    """Define the admin pages for users."""
    ordering = ['id']
    list_display = ['email', 'name']
```

### What this does

- `ordering = ['id']`  
    Users will be sorted by database ID.
    
- `list_display = ['email', 'name']`  
    The admin list page will show only the **email** and **name** columns.
    

This matches the previous test you wrote (asserting name + email appear).

---

## ✅ Register the Custom User Model in Admin

At the bottom of `admin.py`:

```python
admin.site.register(models.User, UserAdmin)
```

### Why pass `UserAdmin`?

If you do:

```python
admin.site.register(models.User)
```

Django will register the model with default settings → your custom ordering/list_display won’t apply.

---

## 🐛 Common Bug: `order` vs `ordering`

The instructor hits a failure because of a typo:

- ❌ `order = ['id']`
    
- ✅ `ordering = ['id']`
    

Why it breaks:

- Django falls back to default ordering from `BaseUserAdmin`
    
- Default admin expects fields like `username`
    
- But your custom user model likely **doesn’t have `username`**
    
- → causes errors
    

Fixing it to `ordering` makes tests pass.

---

## ✅ Run the tests again

After registering the model and fixing the typo, the previous admin test should pass (the admin URL now exists and the list shows name/email).
