# Django Admin – Support Creating Users (Add User Page) with `add_fieldsets`

## 🎯 Main Goal

Enable the **“Add user”** page in Django Admin for your **custom User model**.

You’ll do it with TDD:

1. Write a failing test for the admin “create user” page
    
2. Customize `UserAdmin` to support the fields your custom model uses
    
3. Re-run tests → pass
    
4. Confirm in the browser by creating a new user via admin
    

---

## ✅ Step 1 — Add a Test for the Create User Page

File: `core/tests/test_admin.py`

Add a new test at the bottom.

### Admin URL used

Admin “add page” URL pattern:

- `admin:<app_label>_<model_name>_add`
    

For your custom user model:

- `admin:core_user_add`
    

No ID needed because you’re creating a new object.

### Test idea

- Use `reverse()` to generate the URL
    
- `GET` the page
    
- Assert HTTP status code is **200**
    

Conceptually:

```python
def test_create_user_page(self):
    """Test the create user page works."""
    url = reverse('admin:core_user_add')
    res = self.client.get(url)

    self.assertEqual(res.status_code, 200)
```

### Expected result

The test fails initially, for the same reason as before: Django’s default admin add form expects default user fields (like username), which your custom model doesn’t have.

---

## ✅ Step 2 — Fix Admin by Adding `add_fieldsets`

Go to: `core/admin.py`

Inside your `UserAdmin` class, add **add_fieldsets** (not `and_fields`, not `add_field_sets`, etc.).

### Why this is needed

- `fieldsets` controls the _edit/change page_
    
- `add_fieldsets` controls the _create/add page_
    
- Without `add_fieldsets`, Django uses the default “add user” form that doesn’t match your custom user model fields.
    

---

## 🧩 `add_fieldsets` Configuration

The lesson sets a single section with:

- `email`
    
- `password1`
    
- `password2`
    
- `name`
    
- `is_active`
    
- `is_staff`
    
- `is_superuser`
    

And also adds `classes: ('wide',)` which is optional UI formatting.

Conceptually:

```python
add_fieldsets = (
    (None, {
        'classes': ('wide',),
        'fields': (
            'email',
            'password1',
            'password2',
            'name',
            'is_active',
            'is_staff',
            'is_superuser',
        ),
    }),
)
```

### ⚠️ Common mistakes shown in the lesson

#### 1) Typo in variable name

- ❌ `and_fields`
    
- ✅ `add_fieldsets`
    

#### 2) Missing comma in a 1-item tuple

Because this is a tuple-of-tuples, when there’s only one section, you **must** keep the trailing comma after the section tuple, otherwise Python won’t treat it as a tuple correctly.

Example of what _must_ be true:

```python
add_fieldsets = (
    (None, {...}),
)  # <— comma matters when there's only one item
```

---

## 🎨 Note About `classes = ('wide',)`

This is purely UI-related.

- It allows adding CSS class styling to the form layout
    
- It can make the page look slightly cleaner
    
- Optional: removing it usually won’t break functionality

## 🧠 Key Takeaways

- Admin add page requires **`add_fieldsets`** for custom user models
    
- Write a test for `admin:core_user_add` first (TDD)
    
- Use `password1` and `password2` fields on the add form
    
- Be careful with tuple syntax and commas
    
- `classes: ('wide',)` is optional styling
