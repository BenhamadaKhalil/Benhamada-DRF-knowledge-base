# 🔐 Security Checklist

> Organised by the **OWASP API Security Top 10**, because that's the list attackers work from.

---

## 🥇 A01 — Broken Object Level Authorization

**The #1 API vulnerability, every year.** Also called IDOR: change the ID in the URL, get someone else's data.

```http
GET /api/recipe/recipes/1/     ← yours
GET /api/recipe/recipes/2/     ← ...also returns data?
```

```python
# ❌ any authenticated user reads any recipe
class RecipeViewSet(viewsets.ModelViewSet):
    queryset = Recipe.objects.all()
    permission_classes = [IsAuthenticated]

# ✅ the row simply doesn't exist for you
    def get_queryset(self):
        return self.queryset.filter(user=self.request.user)
```

- [ ] Every viewset with user-owned data overrides `get_queryset()`
- [ ] A `test_x_limited_to_user` test exists for every owned resource
- [ ] You have manually confirmed user B gets `404` on user A's object

> [!CAUTION] `IsAuthenticated` is not authorization
> It proves someone is *a* user. It says nothing about whether they're *the* user. This distinction is the whole of A01. See [[5.Custom Permissions]].

## 🔑 A02 — Broken Authentication

- [ ] Tokens expire — see [[6.Token vs JWT vs Session]]
- [ ] `/api/user/token/` is throttled tightly — see [[2.Throttling and Rate Limiting]]
- [ ] Password validators are enabled:
  ```python
  AUTH_PASSWORD_VALIDATORS = [
      {"NAME": "django.contrib.auth.password_validation.UserAttributeSimilarityValidator"},
      {"NAME": "django.contrib.auth.password_validation.MinimumLengthValidator",
       "OPTIONS": {"min_length": 10}},
      {"NAME": "django.contrib.auth.password_validation.CommonPasswordValidator"},
      {"NAME": "django.contrib.auth.password_validation.NumericPasswordValidator"},
  ]
  ```
- [ ] Login errors are **generic**: `"Unable to log in with provided credentials."` — never `"No user with that email"`, which is a free account-enumeration oracle
- [ ] Passwords are hashed by Django (`set_password`), never stored or logged

## 📤 A03 — Excessive Data Exposure

Serializers are your data-egress boundary. `fields = "__all__"` hands over whatever the model happens to have — including the columns you add next year.

```python
# ❌ ships password hash, is_superuser, and every future field
class UserSerializer(serializers.ModelSerializer):
    class Meta:
        model = get_user_model()
        fields = "__all__"

# ✅ explicit allow-list
class UserSerializer(serializers.ModelSerializer):
    class Meta:
        model = get_user_model()
        fields = ["id", "email", "name"]
        extra_kwargs = {"password": {"write_only": True, "min_length": 10}}
```

- [ ] No serializer uses `fields = "__all__"`
- [ ] `password` is `write_only`
- [ ] Internal flags (`is_staff`, `is_superuser`) are not exposed or writable
- [ ] Error responses don't leak stack traces (`DEBUG=False`)

## 📈 A04 — Unrestricted Resource Consumption

- [ ] Pagination on every list endpoint — [[1.Pagination]]
- [ ] `max_page_size` set, so `?page_size=999999` can't be used against you
- [ ] Throttling on anonymous and authenticated traffic
- [ ] `DATA_UPLOAD_MAX_MEMORY_SIZE` and nginx's `client_max_body_size` bounded
- [ ] Image uploads validated for type **and** dimensions, not just size

```python
# app/app/settings.py
DATA_UPLOAD_MAX_MEMORY_SIZE = 5 * 1024 * 1024      # 5 MB
FILE_UPLOAD_MAX_MEMORY_SIZE = 5 * 1024 * 1024
```

> [!WARNING] Image bombs
> A 20 KB PNG can decompress to gigabytes in Pillow. Validate dimensions before processing:
> ```python
> from PIL import Image
>
> def validate_image(f):
>     img = Image.open(f)
>     if img.width * img.height > 50_000_000:
>         raise ValidationError("Image dimensions too large.")
> ```

## 🏗️ A05 — Broken Function Level Authorization

- [ ] Admin-only actions actually check `IsAdminUser`, not just "the UI doesn't show the button"
- [ ] `DEFAULT_PERMISSION_CLASSES` is `IsAuthenticated` — fail closed
- [ ] Custom `@action` methods on viewsets have their own permissions (they do **not** inherit per-action logic automatically)
- [ ] `/admin/` is not on a predictable path, or is IP-restricted

## 📥 A06 — Mass Assignment

A client sends a field you never intended to accept, and `ModelSerializer` happily writes it.

```python
# request body
{"email": "a@b.com", "password": "x", "is_staff": true}
```

If `is_staff` is in `fields`, that request just made an admin.

- [ ] `fields` lists only what clients may write
- [ ] `read_only_fields` covers `id`, timestamps, and ownership
- [ ] `user` is set from `request.user` server-side, never from the payload:
  ```python
  def perform_create(self, serializer):
      serializer.save(user=self.request.user)
  ```

## ⚙️ A07 — Security Misconfiguration

```bash
docker compose -f docker-compose-deploy.yml run --rm app sh -c "python manage.py check --deploy"
```

- [ ] `DEBUG = False`
- [ ] `SECRET_KEY` from the environment, unique per environment
- [ ] `ALLOWED_HOSTS` explicit — never `["*"]`
- [ ] `SECURE_SSL_REDIRECT`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` all `True`
- [ ] `SECURE_HSTS_SECONDS` set (after HTTPS is confirmed working)
- [ ] `X_FRAME_OPTIONS = "DENY"`
- [ ] `CORS_ALLOW_ALL_ORIGINS = False`; list origins explicitly
- [ ] Containers run as a non-root user
- [ ] Database port not published to the internet

See [[6.Post-Deploy Checklist]] for the full settings block.

## 💉 A08 — Injection

Django's ORM parameterises queries, so you are safe **unless you opt out**:

```python
# ❌ SQL injection
Recipe.objects.raw(f"SELECT * FROM core_recipe WHERE title = '{title}'")
Recipe.objects.extra(where=[f"title = '{title}'"])

# ✅ parameterised
Recipe.objects.raw("SELECT * FROM core_recipe WHERE title = %s", [title])

# ✅ better: don't use raw
Recipe.objects.filter(title=title)
```

- [ ] No f-strings or `%`-formatting inside `raw()` / `extra()` / `RawSQL`
- [ ] No `eval`, `exec`, or `pickle.loads` on anything a client sent
- [ ] File paths built from user input are sanitised — `../../etc/passwd` in a filename is a real upload attack

---

## 📦 A09 — Improper Inventory Management

- [ ] You know every deployed environment and every public endpoint
- [ ] Staging is not on the public internet with production data in it
- [ ] Old API versions are documented as deprecated with a removal date — [[12.Versioning an API]]
- [ ] `/api/docs/` is either intentionally public or behind auth. **Decide deliberately** — it is a complete map of your API for anyone who finds it.

---

## 🔄 A10 — Unsafe Consumption of Third-Party APIs

- [ ] Every outbound HTTP call has a timeout — `requests.get(url, timeout=5)`. Without one, a hung upstream hangs your worker indefinitely.
- [ ] Third-party responses are validated before use, not trusted
- [ ] Webhook payloads verify their signature before you act on them
- [ ] External calls happen in a [[9.Background Jobs with Celery|background task]], not inside a request

```yaml
      - name: Security scan

```

Enable **Dependabot** on the repo. Most real-world compromises come through a dependency, not through your code.

## 🎯 If you only do five things

1. `get_queryset()` filters by `request.user` on **every** owned resource
2. `DEBUG=False`, `SECRET_KEY` from env, `ALLOWED_HOSTS` explicit
3. Throttle the login endpoint
4. No `fields = "__all__"`, ever
5. HTTPS with secure cookie flags

That covers the overwhelming majority of what actually gets exploited in small APIs.
