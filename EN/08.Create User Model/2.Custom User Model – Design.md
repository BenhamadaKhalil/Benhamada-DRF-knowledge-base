# 👤 Custom User Model – Design

In this section, we design our **custom Django user model** before implementing it.

---

# 🧱 Fields in Our Custom User Model

We will define the following fields:

## 1️⃣ `email`

- Used as login identifier
    
- Replaces username
    
- Must be unique
    
- Will be normalized (lowercased domain part)
    

```python
email = models.EmailField(unique=True)
```

---

## 2️⃣ `name`

- Free text field
    
- Stores the user’s display name
    

```python
name = models.CharField(max_length=255)
```

---

## 3️⃣ `is_active`

- Boolean field
    
- Determines if user account is active
    
- Allows disabling login without deleting account
    

```python
is_active = models.BooleanField(default=True)
```

💡 Use case:

- Suspend user temporarily
    
- Keep historical data
    
- Prevent login
    

---

## 4️⃣ `is_staff`

- Boolean field
    
- Determines access to Django Admin
    
- Required for admin login
    

```python
is_staff = models.BooleanField(default=False)
```

---

# 🏗️ User Model Structure Summary

|Field|Type|Purpose|
|---|---|---|
|email|EmailField|Login identifier|
|name|CharField|Display name|
|is_active|Boolean|Enable/disable login|
|is_staff|Boolean|Admin access|

# 🧠 User Model Manager

Now let’s talk about the **User Manager**.

The manager controls how user objects are created.

---

# 🎯 Why Do We Need a Custom Manager?

Because:

- We are replacing username with email
    
- We must hash passwords properly
    
- We must support `createsuperuser` CLI command
    
- Django requires special logic for custom user models
    

---

# 🔐 Password Hashing

Passwords must NEVER be stored as plain text.

Django provides:

```python
set_password()
```

This:

- Hashes the password
    
- Uses a one-way encryption algorithm
    
- Stores hashed version in DB
    

✔ Good:

```
pbkdf2_sha256$...
```

❌ Bad:

```
mypassword123
```

Security rule:

> Always hash passwords using Django's built-in methods.

---

# 🏗️ BaseUserManager

We inherit from:

```python
BaseUserManager
```

Why?

It provides:

- `normalize_email()`
    
- Internal user management helpers
    
- Integration with Django auth system
    

---

# 📧 normalize_email()

This ensures email consistency:

Example:

```
User@Gmail.com
```

Becomes:

```
User@gmail.com
```

Prevents duplicates and inconsistencies.

---

# 🛠 Methods We Must Implement

## 1️⃣ `create_user()`

Used to:

- Create normal users
    
- Hash password
    
- Normalize email
    
- Validate required fields
    

---

## 2️⃣ `create_superuser()`

Used by:

```bash
python manage.py createsuperuser
```

Must:

- Set `is_staff = True`
    
- Set `is_superuser = True`
    
- Call `create_user()`
    

---

# 🧠 Manager Responsibilities Summary

|Method|Purpose|
|---|---|
|create_user|Create normal user|
|create_superuser|Create admin user|
|normalize_email|Standardize email|
|set_password|Secure password hashing|

# ⚠️ Important Design Decisions

✔ Use email as username

✔ Future-proof the system

- **PermissionsMixin** = Admin + permission support
    
- **AbstractBaseUser** = Authentication foundation
