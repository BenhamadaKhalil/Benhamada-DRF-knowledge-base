# Testing the Custom User Model in Django (Manual Verification)

## 1️⃣ Start the Development Server

Run:

```bash
docker compose up
```

What happens:

- Starts the Django development server
    
- Applies migrations automatically if needed
    
- If no model changes were made, migrations won’t re-run
    

---

## 2️⃣ Open the App in Browser

Go to:

```
http://127.0.0.1:8000/
```

Then open Django admin:

```
http://127.0.0.1:8000/admin/
```

If everything is correct:

- You should see the Django admin login page.
    

---

## 3️⃣ Create a Superuser (Using CLI)

Open a new terminal tab and run:

```bash
docker compose run --rm app sh -c "python manage.py createsuperuser"
```

You’ll be prompted for:

- Email
    
- Password
    
- Password confirmation
    

Example:

```
Email: admin@example.com
Password: ********
Superuser created successfully.
```

Important:

- Since we replaced `username` with `email`, Django now asks for **email** instead of username.
    
- This confirms your custom user model is correctly configured.
    

---

## 4️⃣ Log into Django Admin

Go back to:

```
http://127.0.0.1:8000/admin/
```

Enter:

- Email
    
- Password
    

If login works ✅:

- Your custom user model
    
- `create_superuser`
    
- Authentication integration
    
- Permissions system
    

are all working correctly.

---

## 🔎 Why This Works

Because:

- You set in `settings.py`:
    

```python
AUTH_USER_MODEL = 'core.User'
```

- Your `User` model extends:
    
    - `AbstractBaseUser`
        
    - `PermissionsMixin`
        
- Your `UserManager` implements:
    
    - `create_user`
        
    - `create_superuser`
        

Django CLI automatically calls `create_superuser()` when running:

```bash
python manage.py createsuperuser
```

That’s why spelling and indentation matter A LOT.
