# 🍲 Implementing the Recipe Model in Django

## 🎯 Core Concept

After writing the **test for creating a recipe**, the next step is to **implement the actual model** in Django.

The **Recipe model** represents a recipe stored in the database and contains fields such as:

- user (owner of the recipe)
- title
- description
- preparation time
- price
- external link

> [!INFO]
> In **TDD**, the normal workflow is:
>
> 1. Write a failing test  
> 2. Implement the model / feature  
> 3. Run tests until they pass

---

# 💻 Implementation

## 1️⃣ Import the Settings

At the top of `core/models.py`:

```python
from django.conf import settings
from django.db import models
````

We import **settings** because we will reference the **custom user model**.

---

## 2️⃣ Create the Recipe Model

Inside `core/models.py`:

```python
class Recipe(models.Model):
    """Recipe object"""

    user = models.ForeignKey(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE
    )
    title = models.CharField(max_length=255)
    description = models.TextField(blank=True)
    time_minutes = models.IntegerField()
    price = models.DecimalField(max_digits=5, decimal_places=2)
    link = models.CharField(max_length=255, blank=True)

    def __str__(self):
        return self.title
```

---

# 🔍 Field Breakdown

## 👤 User Field

```python
user = models.ForeignKey(
    settings.AUTH_USER_MODEL,
    on_delete=models.CASCADE
)
```

This creates a **relationship between Recipe and User**.

Meaning:

```
User → can have many recipes
Recipe → belongs to one user
```

> [!INFO]  
> Always reference the user model using:

```
settings.AUTH_USER_MODEL
```

This keeps your code **compatible with custom user models**.

---

## ⚠️ on_delete=models.CASCADE

```python
on_delete=models.CASCADE
```

This means:

```
If User is deleted
     ↓
All their recipes are deleted automatically
```

Example:

```
User Khalil
 ├── Recipe 1
 ├── Recipe 2
 └── Recipe 3

Delete Khalil
     ↓
All recipes deleted
```

> [!TIP]  
> This is useful for **data privacy compliance** because deleting a user removes all related data.

---

## 📝 Title Field

```python
title = models.CharField(max_length=255)
```

Stores the **recipe name**.

Example:

```
Chicken Curry
Spaghetti Carbonara
Chocolate Cake
```

`CharField` is used for **short text fields**.

---

## 📄 Description Field

```python
description = models.TextField(blank=True)
```

Stores **long-form text** describing the recipe.

Example:

```
A delicious homemade pasta recipe made with fresh ingredients.
```

### Difference Between CharField and TextField

|Field|Use Case|
|---|---|
|CharField|Short text|
|TextField|Long text / paragraphs|

> [!INFO]  
> Some databases treat **TextField differently for performance**.

---

## ⏱️ Time in Minutes

```python
time_minutes = models.IntegerField()
```

Represents **how long the recipe takes to prepare**.

Example:

```
Omelette → 5 minutes
Pasta → 20 minutes
Lasagna → 90 minutes
```

---

## 💰 Price Field

```python
price = models.DecimalField(max_digits=5, decimal_places=2)
```

Defines the **estimated cost of making the recipe**.

Example:

```
5.50
12.00
99.99
```

### Explanation

|Parameter|Meaning|
|---|---|
|`max_digits=5`|total digits allowed|
|`decimal_places=2`|digits after decimal|

Example allowed values:

```
999.99
45.50
12.00
```

> [!CAUTION]  
> For **real financial systems**, storing currency as **integers (cents)** is recommended to avoid rounding issues.

---

## 🔗 Link Field

```python
link = models.CharField(max_length=255, blank=True)
```

Stores an **external link for the recipe**.

Example:

```
https://myrecipes.com/chicken-curry
```

`blank=True` means the field is **optional**.

---

# 🧾 String Representation

```python
def __str__(self):
    return self.title
```

This controls **how the object is displayed as text**.

Example:

```
print(recipe)
```

Output:

```
Chicken Curry
```

> [!TIP]  
> This is especially useful inside the **Django Admin panel**.

Without it, Django would show:

```
Recipe object (1)
```

---

# ⚙️ Register Model in Django Admin

Open:

```
core/admin.py
```

Add:

```python
from django.contrib import admin
from core import models

admin.site.register(models.Recipe)
```

Now the **Recipe model appears in Django Admin**.

---

# 🧩 Create Migration

Run:

```bash
docker compose run --rm app sh -c "python manage.py makemigrations"
```

Django generates a migration file:

```
core/migrations/000X_recipe.py
```

This file contains instructions for creating the **database table**.

> [!INFO]  
> Migration files are **auto-generated** and normally should not be edited manually.

---

# ▶️ Run Tests Again

Run:

```bash
docker compose run --rm app sh -c "python manage.py test"
```

Expected result:

```
OK
```

The test now **passes**, confirming that the model works.

```python

```
