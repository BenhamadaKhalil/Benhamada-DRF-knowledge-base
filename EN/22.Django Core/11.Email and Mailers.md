# 📧 Email and Mailers

> 📖 [topics/email](https://docs.djangoproject.com/en/6.1/topics/email/)
>
> **Django 6.1 replaced the entire `EMAIL_*` settings family with `MAILERS`.** The old settings still work but are deprecated and go away in **Django 7.0**.

---

## 🆕 `MAILERS`

```python
# app/app/settings.py
MAILERS = {
    "default": {
        "BACKEND": "django.core.mail.backends.smtp.EmailBackend",
        "OPTIONS": {
            "host": os.environ["EMAIL_HOST"],
            "port": 587,
            "use_tls": True,
            "username": os.environ["EMAIL_USER"],
            "password": os.environ["EMAIL_PASSWORD"],
            "timeout": 10,
        },
    },
    "notifications": {
        "BACKEND": "example.third.party.EmailBackend",
        "OPTIONS": {"api_key": os.environ["POSTMARK_KEY"], "region": "eu"},
    },
}
```

Shaped exactly like `DATABASES` and `CACHES` — named aliases, each with a backend and options. **`"default"` is used when you don't say otherwise.**

```python
from django.core.mail import send_mail

send_mail(
    "Recipe saved",
    "Your recipe is live.",
    "noreply@example.com",
    ["user@example.com"],
    using="notifications",        # ← new in 6.1
)
```

> [!TIP] Why this is better than `EMAIL_*`
> The old settings allowed exactly **one** configuration per project. Every real product ends up wanting two — transactional mail through a reliable provider, and bulk/marketing mail through a cheaper one — and had to hand-build connections with `get_connection()`. `MAILERS` makes that a one-word argument.

## 🔄 Migrating from `EMAIL_*`

| Deprecated | Replacement |
| --- | --- |
| `EMAIL_BACKEND` | `MAILERS["default"]["BACKEND"]` |
| `EMAIL_HOST` | `OPTIONS["host"]` |
| `EMAIL_PORT` | `OPTIONS["port"]` |
| `EMAIL_HOST_USER` | `OPTIONS["username"]` |
| `EMAIL_HOST_PASSWORD` | `OPTIONS["password"]` |
| `EMAIL_USE_TLS` / `EMAIL_USE_SSL` | `OPTIONS["use_tls"]` / `["use_ssl"]` |
| `EMAIL_TIMEOUT` | `OPTIONS["timeout"]` |
| `EMAIL_FILE_PATH` | `OPTIONS["file_path"]` |
| `mail.get_connection()` | `mailers["alias"]` |
| `connection=` argument | `using="alias"` |
| `fail_silently=` argument | `OPTIONS["fail_silently"]` |
| `auth_user=` / `auth_password=` | `OPTIONS["username"]` / `["password"]` |

```python
# ❌ deprecated
connection = get_connection(host="smtp.x.com", username=u, password=p)
send_mail("s", "m", "f", ["t"], connection=connection, fail_silently=True)

# ✅
send_mail("s", "m", "f", ["t"], using="default")
```

> [!CAUTION] `using` and the old arguments are mutually exclusive
> Passing `using=` together with `connection=`, `fail_silently=`, `auth_user=` or `auth_password=` raises `TypeError`. Migrate a call site completely, not halfway.

**Timeline:** on 6.1, no `MAILERS` = deprecation warnings but the old behaviour still works. On **7.0**, no `MAILERS` = `MailerDoesNotExist`.

## 🔌 Backends

| Backend | For |
| --- | --- |
| `smtp.EmailBackend` | production |
| `console.EmailBackend` | development — prints to stdout *(the new project default)* |
| `filebased.EmailBackend` | development — writes `.log` files to `file_path` |
| `locmem.EmailBackend` | **tests** — appends to `django.core.mail.outbox` |
| `dummy.EmailBackend` | discards everything |

```python
# development
MAILERS = {
    "default": {"BACKEND": "django.core.mail.backends.console.EmailBackend"},
}
```

## ✉️ Sending

```python
from django.core.mail import send_mail, EmailMessage, EmailMultiAlternatives

# simplest
send_mail("Subject", "Body", "from@example.com", ["to@example.com"])

# full control
msg = EmailMessage(
    subject="Your recipe",
    body="Plain text body",
    from_email="noreply@example.com",
    to=["user@example.com"],
    reply_to=["support@example.com"],
    headers={"X-Recipe-ID": "42"},
)
msg.attach("recipe.pdf", pdf_bytes, "application/pdf")
msg.send(using="notifications")

# HTML + plain-text fallback
msg = EmailMultiAlternatives("Subject", text_body, "noreply@example.com", ["user@example.com"])
msg.attach_alternative(html_body, "text/html")
msg.send()
```

> [!WARNING] `Bcc` in headers is now prohibited
> Django 6.1 raises `ValueError` from `EmailMessage.message()` if `Bcc` appears in `headers`. Use the `bcc=[...]` argument — putting it in a header leaked the list to every recipient, which was the point of the change.

Bulk sending over one connection:

```python
from django.core.mail import mailers

with mailers["notifications"] as backend:
    backend.send_messages([msg1, msg2, msg3])
```

One SMTP handshake instead of three.

## 🧪 Testing email

Django swaps in `locmem` automatically during tests:

```python
from django.core import mail


def test_recipe_email_sent(self):
    """Test one email is sent when a recipe is created."""
    self.client.post(RECIPES_URL, payload, format="json")

    self.assertEqual(len(mail.outbox), 1)
    self.assertEqual(mail.outbox[0].subject, "Recipe saved")
    self.assertIn("user@example.com", mail.outbox[0].to)
    self.assertEqual(mail.outbox[0].sent_using, "notifications")   # new in 6.1
```

`sent_using` is new and genuinely useful: it asserts the message went through the *right* mailer, not just that some mail was sent.

> [!CAUTION] `mail.outbox` doesn't fill if you use `on_commit`
> A plain `TestCase` rolls back, so `transaction.on_commit` callbacks never fire — and email should be in `on_commit`. Wrap the call:
> ```python
> with self.captureOnCommitCallbacks(execute=True):
>     self.client.post(RECIPES_URL, payload, format="json")
> ```
> See [[8.Transactions]].

## 🎯 Sending email properly in this project

Two rules, both covered elsewhere and both non-negotiable:

```python
def perform_create(self, serializer):
    recipe = serializer.save(user=self.request.user)
    transaction.on_commit(
        lambda: send_recipe_email.delay(recipe.id)      # ← Celery task, after commit
    )
```

1. **In a background task** — an SMTP handshake takes 1–3 seconds, and that's a [[9.Background Jobs with Celery|uWSGI worker]] doing nothing.
2. **Inside `on_commit`** — otherwise you email the user about a recipe whose transaction then rolls back.

## ⚠️ Gotchas

- **`MailerDoesNotExist`** → the alias in `using=` isn't in `MAILERS`.
- **`TypeError` on `send_mail`** → mixing `using=` with a deprecated argument.
- **Deprecation warnings after upgrading** → you still have `EMAIL_*` settings. Run `python -Wa manage.py test`.
- **Mail works in dev, silently fails in prod** → `fail_silently` is on. Turn it off and let errors reach [[11.Logging and Observability|Sentry]].
- **`mail.outbox` empty in a test** → `on_commit`, or you're asserting in the wrong test class.
- **Gmail SMTP rejects the login** → app passwords, not your account password. Better: use a transactional provider.
