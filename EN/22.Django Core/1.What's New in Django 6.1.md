## ⭐ The headline feature: fetch modes

The single most relevant change for a DRF API. Django now has a **built-in answer to N+1**.

```python
from django.db import models

# FETCH_ONE (default) — lazy, one query per instance on access
books = Book.objects.all()
for b in books:
    print(b.author.name)          # N queries

# FETCH_PEERS — first access batch-loads for every instance in the QuerySet
books = Book.objects.fetch_mode(models.FETCH_PEERS)
for b in books:
    print(b.author.name)          # 2 queries total

# FETCH_RAISE — raise instead of silently querying
books = Book.objects.fetch_mode(models.FETCH_RAISE)
for b in books:
    print(b.author.name)          # FieldFetchBlocked
```

| Mode | Behaviour |
| --- | --- |
| `FETCH_ONE` | default — lazily fetch for this instance only |
| `FETCH_PEERS` | on first access, fetch for **every** instance from the same QuerySet |
| `FETCH_RAISE` | refuse to fetch; raise `FieldFetchBlocked` |

**Why it matters:** `prefetch_related` requires you to *predict* which relations the serializer will touch. `FETCH_PEERS` reacts to what actually gets accessed. And `FETCH_RAISE` is a genuinely new capability — turn it on in tests and any accidental N+1 becomes a hard failure instead of a slow endpoint.

> [!TIP] It does not replace `select_related`
> A single JOIN is still cheaper than two round trips when you *know* you need the relation. Use explicit `select_related`/`prefetch_related` on your hot list endpoints, and `FETCH_PEERS` as the safety net. See [[4.The N+1 Problem]].

## 🗄️ Database-level `on_delete`

```python
from django.db.models import DB_CASCADE, DB_SET_NULL, DB_SET_DEFAULT

author = models.ForeignKey(Author, on_delete=DB_CASCADE)
```

The delete is handled by a real `ON DELETE` clause in the database rather than by Django walking the object graph in Python. Much faster on large deletes.

> [!WARNING] `DB_CASCADE` does not fire signals
> No `pre_delete`, no `post_delete`. Anything you do in a delete signal — cleaning up uploaded files, invalidating a cache — silently stops happening. See [[7.Signals]].
>
> In this project, `Recipe.image` is deleted by a `post_delete` receiver. Switching that FK to `DB_CASCADE` would orphan every image file on disk.

## 📧 Mailers replace `EMAIL_*`

```python
# ✅ Django 6.1
MAILERS = {
    "default": {
        "BACKEND": "django.core.mail.backends.smtp.EmailBackend",
        "OPTIONS": {"host": "smtp.example.com", "use_tls": True},
    },
    "marketing": {
        "BACKEND": "example.third.party.EmailBackend",
        "OPTIONS": {"region": "africa-1"},
    },
}

send_mail("subject", "message", "from@example.com", using="marketing")
```

Multiple named backends, chosen per send. The whole `EMAIL_BACKEND` / `EMAIL_HOST` / `EMAIL_PORT` / `EMAIL_USE_TLS` family is **deprecated** and goes away in Django 7.0, along with `mail.get_connection()` and the `connection`, `fail_silently`, `auth_user`, `auth_password` arguments.

Full treatment: [[11.Email and Mailers]].

## 🔐 Auth

- PBKDF2 iterations: **1,200,000 → 1,500,000**. Existing hashes upgrade transparently on next login.

- New `Permission.user_perm_str` property.

## 🧮 Other ORM additions

| Addition | What it does |
| --- | --- |
| `JSONNull` | explicit JSON `null`, distinct from SQL `NULL` |
| `UUID4()`, `UUID7()` | database functions — UUID7 is time-sortable |
| `BitAnd` / `BitOr` / `BitXor` | now on all backends, not just PostgreSQL |
| `in_bulk()` after `values()` | chainable |
| `QuerySet.totally_ordered` | tells you whether ordering is deterministic |
| `DecimalField` | `max_digits`/`decimal_places` optional on PostgreSQL, SQLite, Oracle |

## 💥 Backwards-incompatible changes

The ones most likely to bite an existing project:

| Change | Impact |
| --- | --- |
| `first()` / `last()` no longer auto-order by PK when ordering is cleared | a query you thought was deterministic may not be — see `totally_ordered` |
| SQL aliases now systematically quoted | raw SQL referencing aliases may need adjusting |
| `iexact=None` on a JSONField key transform matches JSON `null`, not `isnull` | JSON filters change meaning |
| Providing `Bcc` in message headers is now prohibited | `EmailMessage.message()` raises `ValueError` |
| `EmailMessage.get_connection()` removed | use `MAILERS` |
| Signed cookies use a new salt derivation | set `SIGNED_COOKIE_LEGACY_SALT_FALLBACK=True` during rollout, or every existing signed cookie is invalidated |
| Cache keys changed for pages with vary headers | first request after deploy is a guaranteed miss |
| `File` always evaluates truthy | `if some_file:` no longer tests for a name |
| `RemoteUserMiddleware` under ASGI no longer auto-prefixes `HTTP_` | affects SSO setups |

> [!CAUTION] The signed-cookie one is a live-traffic trap
> Deploying 6.1 without `SIGNED_COOKIE_LEGACY_SALT_FALLBACK=True` logs out everyone holding a signed cookie, at once. Set it, deploy, let cookies roll over, then remove it.

## 🪦 Deprecations — fix these now, they die in 7.0

```python
# ❌ deprecated in 6.1
Entry.objects.select_related()               # no arguments
Recipe.objects.values_list(flat=True)        # no explicit field
transaction.savepoint()
{"data": None}                               # top-level JSON null

# ✅
Entry.objects.select_related("blog", "author")
Recipe.objects.values_list("id", flat=True)
transaction.savepoint_create()
{"data": JSONNull()}
```

Also deprecated: `ModelAdmin.list_select_related = True`, `BLANK_CHOICE_DASH`, double-dot template lookups (`{{ book..title }}`), `quote_name_unless_alias()`, `parse_bits()` with `takes_context`, and the default `algorithm` in `salted_hmac()` / `base64_hmac()` (sha1 → sha256).

## 🛠️ Upgrading this project

```bash
docker compose run --rm app sh -c "python -Wa manage.py test"
```

`-Wa` surfaces every `RemovedInDjango70Warning`. Work the list to zero before you bump.

Then, in order:

1. **Bump the base images** — `python:3.12-alpine`, `postgres:16-alpine`
2. **Run the test suite with warnings on**, fix deprecations
3. `pip install "Django>=6.1,<6.2"`
4. `python manage.py makemigrations --check --dry-run` — the `Permission` rename generates migrations
5. `python manage.py check --deploy`
6. Set `SIGNED_COOKIE_LEGACY_SALT_FALLBACK=True` **before** deploying, remove it a week later
7. Migrate `EMAIL_*` → `MAILERS`
8. Consider `FETCH_RAISE` in test settings to catch N+1 permanently
