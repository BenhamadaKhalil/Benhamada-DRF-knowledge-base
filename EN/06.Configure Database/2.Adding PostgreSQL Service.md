# Django – Adding PostgreSQL Service to Docker Compose

## 📌 Goal of This Lesson

Add a **PostgreSQL database service** to `docker-compose.yml` and connect it to our Django app.

We will:
- Add the `db` service
- Configure a named volume
- Set environment variables
- Link the app to the database
- Use `depends_on`

---

# 🐳 Step 1 – Add the Database Service

Open:

```
docker-compose.yml
```

Under `services:`, add a new service aligned with `app`.

⚠️ YAML is indentation-sensitive.  
Make sure `db:` is at the same indentation level as `app:`.

```yaml
services:
  app:
    ...

  db:
    image: postgres:13-alpine
```

---

## 🧠 Why `postgres:13-alpine`?

- `13` → specific Postgres version (stable)
- `alpine` → lightweight Linux image
- Smaller image = faster builds + less storage

Official image comes from Docker Hub (PostgreSQL official repository).

---

# 💾 Step 2 – Add a Named Volume

At the **bottom of the file**, add:

```yaml
volumes:
  dev-db-data:
```

This creates a named Docker volume.

---

## Attach Volume to DB Service

Inside `db:`:

```yaml
db:
  image: postgres:13-alpine
  volumes:
    - dev-db-data:/var/lib/postgresql/data
```

### 🔍 What is `/var/lib/postgresql/data`?

This is the directory inside the container where Postgres stores its data.

If this path is wrong → data will NOT persist.

This path comes from official PostgreSQL Docker documentation.

---

# 🔐 Step 3 – Configure Database Environment Variables

Inside `db:`:

```yaml
environment:
  - POSTGRES_DB=devdb
  - POSTGRES_USER=devuser
  - POSTGRES_PASSWORD=changeme
```

## What These Do

When Postgres container starts for the first time:

- Creates database: `devdb`
- Creates user: `devuser`
- Sets password: `changeme`

⚠️ These are development credentials only.

Never hardcode real production credentials in source code.

---

# 🔗 Step 4 – Configure App Service to Connect to DB

Inside `app:` service:

```yaml
environment:
  - DB_HOST=db
  - DB_NAME=devdb
  - DB_USER=devuser
  - DB_PASS=changeme
```

## Important Concept

`DB_HOST=db`

Why?

Because in Docker Compose:
- The hostname of a service = its service name
- Our database service is named `db`
- So Django connects to host `"db"`

Docker automatically handles networking between services.

---

# ⏳ Step 5 – Add `depends_on`

Inside `app:`:

```yaml
depends_on:
  - db
```

This ensures:
- Database container starts before app container

⚠️ Very important:
- This does NOT guarantee database readiness
- It only guarantees startup order
- We'll handle readiness (race condition) later

---

# 🚀 Step 6 – Run Docker Compose

Run:

```bash
docker-compose up
```

If:
- No errors appear
- Database initializes correctly

Then your configuration is valid.

---

# 🧠 Full Mental Model

```
Docker Compose
│
├── app service (Django)
│     ├── uses environment variables
│     ├── connects to host "db"
│     └── depends_on db
│
└── db service (Postgres)
      ├── image: postgres:13-alpine
      ├── environment: DB name, user, password
      └── volume → persistent storage
```

---

# 🔥 Key Takeaways

- YAML indentation matters.
- Service names act as hostnames.
- Named volumes preserve database data.
- Environment variables configure container behavior.
- `depends_on` controls startup order.
- Development credentials are fine locally, never in production.
