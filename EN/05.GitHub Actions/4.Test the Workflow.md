## ✅ GitHub Actions: Test the Workflow (Pass → Fail → Fix)

### Goal

Verify that the **Checks** workflow runs automatically on every `git push`, and understand how to read results when it **passes or fails**.

---

## 1) First run (push to trigger workflow)

### Steps to trigger it

Run in terminal:

```bash
git add .
git commit -am "added github actions"
git push origin main
```

Because the workflow is configured with:

```yml
on: [push]
```

…it will start automatically after the push.

### Where to see it

On GitHub:

- Go to your repository
    
- Click **Actions**
    
- You should see a run named after the **commit message**
    
- It runs on the **main** branch
    

---

## 2) Inspect steps + logs

Click:

- **Checks** workflow → the run → **test and lint** job
    

You’ll see:

- `Login to Docker Hub`
    
- `Checkout`
    
- `Test`
    
- `Lint`
    
- Some extra “post” steps (added automatically by GitHub Actions)
    

### What “success” looks like

- Green ✅
    
- Test step output might show:
    
    - `Ran 0 tests` (normal if you haven’t written tests yet)
        
- Lint step output may be empty (meaning **no lint errors**)
    

---

## 3) Make it fail on purpose (lint error)

### Example: break formatting

Edit a file like `app/app/urls.py` and add something that violates Flake8 rules:

```py
one=one
```

This breaks lint rules because there should be spaces around `=`.

Then push:

```bash
git add .
git commit -am "break linting"
git push origin main
```

---

## 4) Understand failure output

In **Actions → workflow run → job → lint step**, you’ll see errors like:

- **Missing whitespace around operator**
    
- **No newline at end of file**
    

That output tells you:

- Which file
    
- Which line
    
- What rule was violated
    

✅ Fix the code (example):

```py
one = one
```

Or delete the bad line if it’s not needed.

Also ensure the file ends with a newline.

---

## 5) Fix + push again until it’s green

```bash
git add .
git commit -am "fix linting"
git push origin main
```

If it still fails and says **no newline at end of file**, add a newline at the bottom and push again.

✅ Final confirmation:

- Green ✅ on the workflow
    
- No errors under Test and Lint
    

---

## Key takeaways

- Workflows run automatically after **push**
    
- The workflow run title is the **commit message**
    
- Logs show exactly **why** a job failed (file + rule)
    
- Common lint mistakes:
    
    - Missing spaces around operators (`=` etc.)
        
    - Missing newline at end of file
        
- You can configure VS Code to automatically add a newline at EOF to avoid this
