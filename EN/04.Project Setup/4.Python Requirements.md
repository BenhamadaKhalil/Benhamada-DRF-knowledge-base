# 📦 Defining Python Requirements — Obsidian Notes

> 🎯 Goal: Create a `requirements.txt` file to define all Python dependencies for the project.

---

# 🖥️ 1️⃣ Open the Project in VS Code

## Steps

1. Open terminal (CMD / PowerShell / Git Bash / Terminal)
    
2. Navigate to your cloned project:
    

```bash
cd path/to/recipe-app-api
```

3. Open project in VS Code:
    

```bash
code .
```

If `code .` does not work:

- Open VS Code manually
    
- Click **Open Folder**
    
- Select your project folder
    

---

# 📄 2️⃣ Create requirements.txt

In the **root of the project**, create a new file:

```
requirements.txt
```

> 📌 This file lists all Python packages needed for the project.

---

# 🐍 3️⃣ Add Django Dependency

Add this line inside `requirements.txt`:

```
Django>=3.2.4,<3.3
```

---

## 🧠 What This Means

|Part|Meaning|
|---|---|
|`>=3.2.4`|Minimum allowed version|
|`<3.3`|Prevent upgrade to next minor version|

---

## 📌 Why Use Version Ranges?

This ensures:

- ✅ Latest **patch version** installed automatically
    
- ❌ No automatic upgrade to new minor version
    
- ✅ Security & bug fixes included
    
- ❌ Avoid breaking changes
    

---

## 🔎 Version Structure Example

Version format:

```
Major.Minor.Patch
3.2.4
```

- `3` → Major version
    
- `2` → Minor version
    
- `4` → Patch version
    

Patch versions:

- Fix bugs
    
- Improve security
    
- Do NOT break code
    

Minor versions:

- May introduce breaking changes
    

---

## 🧠 Mental Model

```
>=3.2.4,<3.3
→ Stay in Django 3.2 family
→ Always get latest safe fixes
```

---

# 🌐 4️⃣ Add Django REST Framework

Add this line:

```
djangorestframework>=3.12.4,<3.13
```

---

## Why Pin Versions?

In courses and real projects:

- Using exact version range avoids unexpected behavior
    
- Ensures consistency with tutorial steps
    
- Prevents "it works on my machine" issues
    

---

# ⚠️ Important Advice

> 🚫 Do NOT install the latest version randomly during the course.

Use the exact versions provided.

Later, after finishing the course:

- You can practice upgrading dependencies
    
- Learn how to handle breaking changes
    

This reflects real-world development.

---

# 🧠 Real-World Practice Insight

In real projects:

1. You build software on version X
    
2. Later, you upgrade dependencies
    
3. You fix breaking changes
    
4. You test again
    

This is normal maintenance workflow.

---

# 📋 Final requirements.txt Content

Your file should look like:

```
Django>=3.2.4,<3.3
djangorestframework>=3.12.4,<3.13
```

---

# 📦 What Happens Next?

Later, Docker will use this file to install dependencies inside the container using:

```bash
pip install -r requirements.txt
```

requirements.txt = dependency contract

Project stays stable
