# 🐳 Create `Dockerfile` + `.dockerignore` — Obsidian Notes

> 🎯 Goal: Add a **Dockerfile** to build the project image + a **.dockerignore** to keep builds fast and clean, then test `docker build`.

---

# 🧱 1) Create the `Dockerfile`

📍 In the **root** of the project, create a new file named:

```
Dockerfile
```

---

## 🐍 Base Image

Add the base image line:

```dockerfile
FROM python:3.9-alpine3.13
```

> [!info] Why this exact tag?
> 
> - ✅ Python **3.9**
>     
> - ✅ Alpine **3.13** (lightweight Linux)
>     
> - ✅ Same results as the course (important for consistency)
>     

---

## 👤 Maintainer Label

Add a maintainer label:

```dockerfile
LABEL maintainer="your-name-or-site"
```

> [!tip] This helps other devs know who maintains the image.

---

## 🖨️ Python Logs (No Buffering)

```dockerfile
ENV PYTHONUNBUFFERED=1
```

> [!note] Why?  
> Prints logs immediately in Docker (no delay), which is great for debugging.

---

## 📄 Copy Project Files

Copy `requirements.txt` into a temporary location inside the image:

```dockerfile
COPY ./requirements.txt /tmp/requirements.txt
```

Copy your project app folder (we’ll create it):

```dockerfile
COPY ./app /app
```

Set the default working directory:

```dockerfile
WORKDIR /app
```

Expose Django dev server port:

```dockerfile
EXPOSE 8000
```

---

## ⚙️ Install Dependencies + Create a Non-Root User

Add the `RUN` block (single layer, cleaner + faster builds):

```dockerfile
RUN python -m venv /py && \
    /py/bin/pip install --upgrade pip && \
    /py/bin/pip install -r /tmp/requirements.txt && \
    rm -rf /tmp && \
    adduser \
        --disabled-password \
        --no-create-home \
        django-user
```

### ✅ What each part does (simple)

- `python -m venv /py` → creates a virtual environment inside the container
    
- `pip install --upgrade pip` → updates pip
    
- `pip install -r ...` → installs dependencies from `requirements.txt`
    
- `rm -rf /tmp` → removes temp files (keeps image small)
    
- `adduser ... django-user` → creates a **non-root** user (security best practice)
    

> [!important] Why not run as root?  
> If the app is compromised, root gives full control. A limited user reduces damage.

---

## 🧭 Update PATH to use the venv automatically

```dockerfile
ENV PATH="/py/bin:$PATH"
```

> [!tip] Now you can run `python` and `pip` without writing `/py/bin/python`.

---

## 🔒 Switch to the Non-Root User (last line)

```dockerfile
USER django-user
```

> [!warning] Put this at the end  
> Everything before it may require root privileges.

---

## ✅ Final Dockerfile (copy-paste)

```dockerfile
FROM python:3.9-alpine3.13

LABEL maintainer="your-name-or-site"

ENV PYTHONUNBUFFERED=1

COPY ./requirements.txt /tmp/requirements.txt
COPY ./app /app

WORKDIR /app
EXPOSE 8000

RUN python -m venv /py && \
    /py/bin/pip install --upgrade pip && \
    /py/bin/pip install -r /tmp/requirements.txt && \
    rm -rf /tmp && \
    adduser \
        --disabled-password \
        --no-create-home \
        django-user

ENV PATH="/py/bin:$PATH"

USER django-user
```

---

# 🚫 2) Create `.dockerignore`

📍 In the **root** of the project, create:

```
.dockerignore
```

> 🎯 Purpose: exclude files Docker doesn’t need → faster builds + smaller images

---

## ✅ Suggested `.dockerignore` (copy-paste)

```dockerignore
# Git
.git
.gitignore

# Docker
.docker

# Python
app/__pycache__/
app/*/__pycache__/
app/*/*/__pycache__/
app/*/*/*/__pycache__/

# Env files / virtualenvs
.env
.venv
venv/
```

### 🧠 Why ignore these?

- `.git` can be huge (history) ❌
    
- `__pycache__` depends on your OS → can cause issues ❌
    
- local virtualenvs aren’t needed (Docker has its own) ✅
    

> [!note] Why multiple `__pycache__` lines?  
> `.dockerignore` doesn’t fully support “ignore all nested folders” like some tools, so we list multiple depths.

---

# 🧪 3) Test Building the Docker Image

Run in the project root:

```bash
docker build .
```

---

## ⚠️ Common error: missing `app/` folder

If you see an error like “cannot copy app directory”:

✅ Fix: create a folder in the project root named:

```
app/
```

Then run again:

```bash
docker build .
```

---

# ⚡ Docker Build Caching (Good to Know)

> [!tip] First build is slow, second build is fast  
> Docker caches layers, so rerunning `docker build .` becomes much faster after the first successful build.

---

# ✅ Quick Checklist

- ✅ `Dockerfile` created
    
- ✅ `.dockerignore` created
    
- ✅ `app/` folder exists
    
- ✅ `docker build .` succeeds
