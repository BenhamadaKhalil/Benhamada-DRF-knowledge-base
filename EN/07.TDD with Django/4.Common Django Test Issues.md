# 🛠 Common Django Test Issues (And How to Fix Them)

---

## ❌ Problem 1: “Ran 0 tests”

You run:

```bash
python manage.py test
```

And Django says:

```
Ran 0 tests in 0.000s
OK
```

But you wrote tests.  
So why didn’t they run? 🤨

---

## 🔎 Cause #1 — Missing `__init__.py`

If you organize tests inside a folder like this:

```
app/
    tests/
        test_calc.py
```

You MUST add:

```
tests/
    __init__.py
```

Even if it's empty.

### Why?

Without `__init__.py`, Python doesn’t treat the folder as a module.

And Django won’t discover your tests.

✅ Fix:  
Create an empty file:

```bash
touch tests/__init__.py
```

---

## 🔎 Cause #2 — Wrong Indentation

Python uses indentation to define structure.

Bad example ❌:

```python
class CalcTests(SimpleTestCase):

    def test_add(self):
        pass

        def test_subtract(self):  # ❌ Wrong indentation
            pass
```

Here, `test_subtract` is inside `test_add`.

Django will NOT detect it.

Correct version ✅:

```python
class CalcTests(SimpleTestCase):

    def test_add(self):
        pass

    def test_subtract(self):
        pass
```

👉 Always check indentation carefully.

---

## 🔎 Cause #3 — Missing `test_` Prefix

Django only runs:

- Files starting with `test`
    
- Classes inheriting from `TestCase` / `SimpleTestCase`
    
- Methods starting with `test_`
    

This will NOT run ❌:

```python
def check_add(self):
    pass
```

This WILL run ✅:

```python
def test_add(self):
    pass
```

Important rule:

> Every test method must start with `test_`

---

## ❌ Problem 2: Some Tests Run, Others Don’t

Example:

You wrote 10 tests.  
Django says:

```
Ran 5 tests
```

Check:

- Are all method names starting with `test_`?
    
- Are all properly indented?
    
- Are they inside a class inheriting from `TestCase`?
    

---

## ❌ Problem 3: ImportError About Test Modules

Error looks like:

```
ImportError: 'test' module incorrectly imported
Is this module globally installed?
```

This usually happens when you have BOTH:

```
app/
    tests/        ← folder
    tests.py      ← file
```

Python gets confused.

Which one should it import?

### ❌ Bad:

```
tests/
tests.py
```

### ✅ Good (choose ONE):

Option 1:

```
tests.py
```

Option 2:

```
tests/
    __init__.py
    test_calc.py
```

But never both.

---

## 🧠 Quick Debug Checklist

When tests behave weirdly, check:

✔ Do files start with `test_`?  
✔ Do methods start with `test_`?  
✔ Is indentation correct?  
✔ Does `tests/` have `__init__.py`?  
✔ Do you avoid having both `tests.py` AND `tests/`?

---

## 🎯 Pro Tip (Very Useful)

If Django isn’t discovering tests, try:

```bash
python manage.py test app.tests
```

Or even:

```bash
python manage.py test app.tests.test_calc
```

This helps you isolate the problem.

---

## 🧪 Bonus: How Django Finds Tests

Django test discovery looks for:

- Files named `test*.py`
    
- Classes extending `TestCase`
    
- Methods starting with `test_`
    

If any of these rules are broken → test is ignored silently.

That’s why it’s confusing — no error.

---

## 🚨 Why This Confuses Beginners

Because:

- Django doesn’t throw an error.
    
- It just skips tests.
    
- You think everything is fine.
    

But your tests aren’t actually running.

This is dangerous.

---

## 🏁 Summary

Most common Django test issues are:

1️⃣ Missing `__init__.py`  
2️⃣ Bad indentation  
3️⃣ Missing `test_` prefix  
4️⃣ Having both `tests.py` and `tests/`

Fix those, and 90% of problems disappear.
