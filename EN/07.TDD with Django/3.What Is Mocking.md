# 🎭 What Is Mocking?

**Mocking = replacing real dependencies with fake ones during tests.**

You temporarily override behavior so you can:

- 🚫 Avoid real side effects
    
- 🎯 Isolate the code you’re testing
    
- ⚡ Speed up tests
    
- 🔒 Make tests predictable
    

---

# 🤔 Why Do We Need Mocking?

Because real systems are messy.

Imagine this function:

```python
def register_user():
    create_user_in_db()
    send_welcome_email()
```

If you test this normally:

- It writes to the database
    
- It sends real emails 😅
    
- It depends on external services being online
    

That’s bad for unit tests.

---

# 🔥 What Mocking Lets You Do

Instead of sending a real email…

You replace `send_welcome_email()` with a fake version.

So:

- The email is NOT sent
    
- You can verify it was called
    
- The test runs instantly
    

That’s mocking.

---

# 🧠 Core Idea

Mocking helps you test this:

> ❓ Was the function called correctly?

Instead of this:

> ❓ Did the entire real system work?

Unit tests should test _your logic_, not external systems.

---

# 🛑 Problem 1: External Services

Imagine your test depends on:

- Email service
    
- Payment API
    
- Database connection
    
- External REST API
    

If any of these fail → your test fails ❌  
Even if your code is correct.

That makes tests fragile.

Mocking solves this.

---

# 🛑 Problem 2: Side Effects

Imagine:

- Your test sends 5000 emails
    
- Your test charges credit cards
    
- Your test writes to production DB 😬
    

We don’t want that.

Mocking prevents real execution.

---

# 🛑 Problem 3: Slow Tests

Imagine code like this:

```python
while not db_ready:
    time.sleep(5)
```

If your test runs this, it waits 5 seconds.

Now imagine 100 tests like that.

Your test suite becomes slow 🐌

Instead, mock `time.sleep()` so it does nothing.

Now tests run instantly ⚡

---

# 🧰 Tools for Mocking in Python

Python provides built-in tools:

```python
from unittest.mock import Mock, MagicMock, patch
```

---

## 🎯 1. Mock / MagicMock

Fake object that:

- Replaces a real object
    
- Tracks how it was called
    
- Lets you assert behavior
    

Example:

```python
mock = Mock()
mock()
mock.assert_called()
```

---

## 🎯 2. patch

`patch` replaces real objects with mocks temporarily.

Example:

```python
@patch('app.utils.send_email')
def test_register_user(mock_send_email):
    register_user()
    mock_send_email.assert_called_once()
```

This means:

👉 Replace `send_email` with a mock  
👉 Run test  
👉 Check if it was called

No real email sent.

---

# 🧪 Real-Life Example Scenario

Imagine this:

```python
def register_user(email):
    create_user(email)
    send_welcome_email(email)
```

Test WITHOUT mocking:

- Sends real email ❌
    

Test WITH mocking:

- Email not sent
    
- But you verify it was triggered ✅

# 🧠 When Should You Mock?

You usually mock:

- Email sending
    
- External APIs
    
- Payment services
    
- File system
    
- Time delays (`sleep`)
    
- Background jobs
    

You usually DON’T mock:

- Pure business logic
    
- Simple calculations
    
- Functions without external dependencies
    

---

# 💡 Important Mental Model

Mocking does NOT test the external service.

It tests:

> Did your code attempt to call that service correctly?
