# 🌐 Testing Web Requests in Django REST Framework (DRF)

When building APIs, we don’t just test functions.

We test:

- Real HTTP requests
    
- Real endpoints
    
- Real responses
    
- Status codes
    
- Returned data
    

And for that, DRF gives us:

> 🧪 `APIClient`

---

# 🧰 What is APIClient?

`APIClient` is a testing tool provided by:

```python
from rest_framework.test import APIClient
```

It allows you to:

- Send real HTTP requests (GET, POST, PUT, DELETE)
    
- Test API endpoints
    
- Check response status codes
    
- Check response data
    
- Bypass authentication when needed
    

It’s built on top of Django’s test client.

---

# 🚀 Basic Example: Testing a GET Endpoint

Imagine we have this endpoint:

```
/greetings/
```

And it returns:

```json
["Hello", "Bonjour", "Ola"]
```

---

## 📝 Test Example

```python
from rest_framework.test import APIClient
from django.test import SimpleTestCase

class GreetingApiTests(SimpleTestCase):

    def test_get_greetings(self):
        client = APIClient()

        response = client.get('/greetings/')

        self.assertEqual(response.status_code, 200)
        self.assertEqual(
            response.data,
            ['Hello', 'Bonjour', 'Ola']
        )
```

---

# 🔍 What’s Happening Here?

### 1️⃣ Create the client

```python
client = APIClient()
```

This simulates a real user making requests.

---

### 2️⃣ Send HTTP request

```python
response = client.get('/greetings/')
```

You can also use:

```python
client.post()
client.put()
client.patch()
client.delete()
```

Just like real HTTP methods.

---

### 3️⃣ Check Status Code

```python
self.assertEqual(response.status_code, 200)
```

Common status codes:

- 200 → OK
    
- 201 → Created
    
- 400 → Bad Request
    
- 401 → Unauthorized
    
- 403 → Forbidden
    
- 404 → Not Found
    

---

### 4️⃣ Check Returned Data

```python
self.assertEqual(response.data, expected_data)
```

Important:

> `response.data` is already converted into Python objects.

No need to parse JSON manually.

---

# 🔐 Testing Authenticated Endpoints

One powerful feature:

You can force authentication without logging in manually.

Example:

```python
client.force_authenticate(user=user)
```

This avoids:

- Creating login requests
    
- Managing tokens
    
- Handling authentication flow
    

Super useful for clean, isolated tests.

---

# 🎯 Why This Is Important

Testing with APIClient ensures:

✔ Your URLs work  
✔ Your views work  
✔ Your serializers work  
✔ Your authentication works  
✔ Your response format is correct

It tests the full request-response cycle.

That’s much stronger than testing individual functions.

---

# 🧠 Mental Model

Think of it like this:

```
Test → Client → URL → View → Serializer → Response → Assertion
```

You’re testing the entire chain.

---

# 💡 When To Use APIClient vs SimpleTestCase

Use APIClient when:

- Testing APIs
    
- Testing endpoints
    
- Testing HTTP behavior
    
- Testing authentication
    

Use SimpleTestCase when:

- Testing pure logic
    
- No database required
    
- No HTTP needed

# 🏁 Summary

To test APIs in DRF:

1️⃣ Import `APIClient`  
2️⃣ Create client instance  
3️⃣ Make request (`get`, `post`, etc.)  
4️⃣ Check status code  
5️⃣ Check response data

This is how real-world backend APIs are tested.
