# 🔴🟢🔵 Test Driven Development (TDD)

The rule is simple:

1. 🔴 Write the test (it fails)
    
2. 🟢 Write the code (it passes)
    
3. 🔵 Refactor (improve safely)
    

You **write the test FIRST**.

---

## 🧪 Step 1 — Write the Test First (Before Code Exists)

Go to:

```bash
app/app/tests.py
```

Add this new test:

```python
def test_subtract_numbers(self):
    """Test subtracting numbers"""
    result = calc.subtract(10, 15)
    self.assertEqual(result, 5)
```

So now your `tests.py` looks like:

```python
class CalcTests(SimpleTestCase):
    """Test the calc module"""

    def test_add_numbers(self):
        result = calc.add(5, 6)
        self.assertEqual(result, 11)

    def test_subtract_numbers(self):
        result = calc.subtract(10, 15)
        self.assertEqual(result, 5)
```

---

## 🚨 Now Run The Test

```bash
docker-compose run --rm app sh -c "python manage.py test"
```

### What happens?

It FAILS ❌

Error like:

```
AttributeError: module 'app.calc' has no attribute 'subtract'
```

Good 😎  
That’s exactly what we want.

This is the 🔴 phase.

---

## 🟢 Step 2 — Write the Minimum Code to Make It Pass

Go to:

```bash
app/app/calc.py
```

Add the function:

```python
def subtract(x, y):
    """Subtract x from y and return result"""
    return 0
```

Run tests again.

Now error changes to:

```
AssertionError: 0 != 5
```

Good again 😎  
Now the function exists, but logic is wrong.

Now fix it properly:

```python
def subtract(x, y):
    """Subtract x from y and return result"""
    return y - x
```

Run tests again:

```bash
docker-compose run --rm app sh -c "python manage.py test"
```

Now you get:

```
Ran 2 tests

OK
```

That’s the 🟢 phase.

---

## 🧠 Why TDD Is Powerful

You:

- Verified the test actually fails
    
- Verified the logic is correct
    
- Prevented false-positive tests
    
- Guaranteed behavior before writing implementation
    

Most beginners:

> Write code → then maybe write test

Professionals:

> Write expected behavior → then implement code

Huge difference.

---

## 🔵 Step 3 — Refactor Safely

Now that tests pass, you can improve code confidently.

Example:

- Rename variables
    
- Optimize logic
    
- Move functions
    
- Clean formatting
    

As long as tests stay green ✅, you didn’t break behavior.

---

## 🏗 The TDD Mental Model

Think of it like this:

Test = Contract 📜  
Code = Implementation 🔧

You define the contract first.  
Then you make the implementation satisfy it.

---

## ⚡ TDD Cycle Summary

|Phase|What You Do|Expected Result|
|---|---|---|
|🔴 Red|Write test|It fails|
|🟢 Green|Write minimal code|It passes|
|🔵 Refactor|Improve code|Still passes|

---

## 💎 Real-World Insight

In real projects, TDD is most useful when:

- Writing business logic
    
- Complex validation
    
- APIs
    
- Calculations
    
- Authentication
    
- Permissions
    

Not every tiny function needs TDD — but for core logic?  
It’s 🔥.
