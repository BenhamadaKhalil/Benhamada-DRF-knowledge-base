## 🎯 Core Concept

### ✅ Why?

We already wrote tests for a **Manage User** endpoint (`/me/`) that should:

- **Require authentication** (401 if not logged in)
    
- **Allow GET** → return the logged-in user profile
    
- **Allow PATCH/PUT** → update the logged-in user profile
    
- **Disallow POST** → 405 Method Not Allowed
    

### ✅ What?

We implement this by:

1. Extending the existing **UserSerializer** to safely update passwords (hashing!)
    
2. Creating a view using **RetrieveUpdateAPIView**
    
3. Locking it down with **TokenAuthentication** + **IsAuthenticated**
    
4. Wiring the URL name `user:me`
    

> [!CAUTION]  
> If you don’t override the serializer `update()` method, a password update could be saved as **plain text** (security disaster).

---

## 🏗️ Logic Flow

```text
Request (GET/PATCH) to /api/user/me/
  ↓
ManageUserView (RetrieveUpdateAPIView)
  ↓
TokenAuthentication → attaches request.user
  ↓
get_object() → returns request.user
  ↓
UserSerializer
  ↳ GET: serialize user fields
  ↳ PATCH: validate payload → update() hashes password
  ↓
Response 200 OK (profile data)
```

## 💻 Implementation

## 1) Serializer: safely handle password updates

📂 `app/user/serializers.py`

> [!CODE]  
> We reuse the same serializer for create + update, but we **override `update()`** to hash the password correctly.

```python
from django.contrib.auth import get_user_model
from rest_framework import serializers


class UserSerializer(serializers.ModelSerializer):
    """Serializer for the user object."""

    class Meta:
        model = get_user_model()
        fields = ['email', 'password', 'name']
        extra_kwargs = {'password': {'write_only': True, 'min_length': 5}}

    def create(self, validated_data):
        """Create and return a user with encrypted password."""
        return get_user_model().objects.create_user(**validated_data)

    def update(self, instance, validated_data):
        """Update and return user."""
        password = validated_data.pop('password', None)

        # Update remaining fields (name/email/etc.) using default ModelSerializer logic
        user = super().update(instance, validated_data)

        # If password was provided, hash it properly
        if password:
            user.set_password(password)
            user.save()

        return user
```

### 🧠 Key detail: `pop('password', None)`

- `pop()` **removes** password from `validated_data` so `super().update()` won’t store it raw.
    
- Password becomes optional in updates (user may update only name/email).
    

> [!PROTIP]  
> Use `pop()` not `get()` here. `get()` leaves `password` in the dict and risks plain-text assignment by default update behavior.

## 2) View: Retrieve + Update authenticated user

📂 `app/user/views.py`

```python
from rest_framework import generics, authentication, permissions
from user.serializers import UserSerializer


class ManageUserView(generics.RetrieveUpdateAPIView):
    """Manage the authenticated user."""
    serializer_class = UserSerializer
    authentication_classes = [authentication.TokenAuthentication]
    permission_classes = [permissions.IsAuthenticated]

    def get_object(self):
        """Retrieve and return the authenticated user."""
        return self.request.user
```

### 🔐 Authentication vs Permission (important distinction)

- **Authentication**: who are you? (token proves identity)
    
- **Permission**: what can you do? (must be logged in)
    

> [!INFO]  
> `TokenAuthentication` attaches the authenticated user to `request.user`, so returning `self.request.user` makes `/me/` always operate on the current user.

---

## 3) URL: map `/me/` to the view

📂 `app/user/urls.py`

```python
from django.urls import path
from user import views

urlpatterns = [
    path('me/', views.ManageUserView.as_view(), name='me'),
]
```

✅ This matches the tests that use:

```python
reverse('user:me')
```

## ⚡ Pro-Tips & Gotchas

> [!CAUTION]  
> **Never** assign `user.password = "newpass"` directly. Always use:

- `user.set_password("newpass")`
    

> [!PROTIP]  
> `RetrieveUpdateAPIView` is perfect for `/me/`:

- GET → retrieve
    
- PATCH/PUT → update
    
- POST isn’t supported by design → naturally returns 405
    

> [!PROTIP]  
> Overriding `get_object()` avoids needing lookup fields (like `/users/<id>/`) and prevents users from accessing others.
