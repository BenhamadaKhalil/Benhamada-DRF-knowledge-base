## 🎯 Core Concept

### ✅ Why?

After finishing implementation + unit tests, we manually verify the API end-to-end using the **Swagger/OpenAPI docs UI**. This simulates how a real client app would:

- Create a user
    
- Log in (get token)
    
- Call protected endpoints like `/me/`
    
- Patch profile fields
    

### ✅ What?

We use:

- `docker compose up` to run the server
    
- `/api/docs` to interact with endpoints
    
- **Token Authentication** header: `Token <token_value>`
    

> [!INFO]  
> Swagger “Execute” performs **real HTTP requests** to your running API—this is not a mock.

---

## 🏗️ Logic Flow (Manual Test Journey)

```text
docker compose up
  ↓ (migrations run)
Open /api/docs
  ↓
POST /api/user/create/  (register)
  ↓
POST /api/user/token/   (obtain token)
  ↓
Authorize: "Token <token>"
  ↓
GET /api/user/me/       (see profile)
  ↓
PATCH /api/user/me/     (update name only)
  ↓
GET /api/user/me/       (confirm persisted)
```

## 🧰 Running the App (Docker)

```bash
docker compose up
```

### 🗃️ Important: Migrations after enabling Token App

When you added:

- `rest_framework.authtoken` in `INSTALLED_APPS`
    

DRF adds **new DB tables** for tokens, so migrations must run.

> [!CAUTION]  
> If your server was already running, stop it (`Ctrl + C`) and run `docker compose up` again so token migrations apply.

## 🔍 Open Swagger / API Docs

Open:

- `http://127.0.0.1:8000/api/docs`
    

You should now see a **User** section containing:

- Create endpoint
    
- Token endpoint
    
- `/me/` endpoint (GET, PATCH, PUT)
    

---

## 🧪 Manual Testing Steps (Swagger UI)

## 1) Verify `/me/` requires auth

Try:

- `GET /api/user/me/` → **Execute**
    

Expected:

- **401 Unauthorized**
    

> [!INFO]  
> This confirms your `TokenAuthentication` + `IsAuthenticated` are enforced.

---

## 2) Create a user via Swagger form

Use:

- `POST /api/user/create/` → **Try it out**
    

Tip: switch request body to **form-data** to get a friendly form UI (instead of JSON).

Example data:

- email: `user2@example.com`
    
- password: `somepassword`
    
- name: `User 2`
    

Expected:

- **201 Created**
    
- Response shows email + name
    

---

## 3) Obtain a token (login)

Use:

- `POST /api/user/token/` → **Try it out**
    
- Provide the same email/password you registered with
    

Expected:

- **200 OK**
    
- Response contains:
    

```json
{
  "token": "xxxxxxxxxxxxxxxxxxxx"
}
```

> [!INFO]  
> In a real frontend app, you would store this token (e.g., secure storage) and reuse it on future requests.

---

## 4) Authorize in Swagger (critical format)

Click **Authorize** in Swagger UI.

Use this exact format:

```text
Token <paste_token_here>
```

Rules:

- `Token` must have **capital T**
    
- Must include a **space**
    
- Must use the **exact token returned** by `/token/`
    

> [!CAUTION]  
> If you miss the space or write `token` lowercase, auth will fail and `/me/` stays 401.

After clicking **Authorize**, Swagger automatically adds an `Authorization` header to all subsequent requests.

---

## 5) GET `/me/` again (should work now)

- `GET /api/user/me/` → Execute
    

Expected:

- **200 OK**
    
- Response contains your authenticated user profile
    

This proves your `/me/` endpoint is correctly returning `request.user`.

---

## 6) PATCH `/me/` to update only one field

Why PATCH vs PUT?

- **PATCH**: partial update (send only the fields you want to change)
    
- **PUT**: replaces the full object (typically include all fields)
    

In Swagger:

- `PATCH /api/user/me/` → Try it out
    
- Remove fields you are NOT changing (e.g., delete email/password)
    
- Send only:
    

```json
{
  "name": "User 2 New Name"
}
```

Expected:

- **200 OK**
    
- Response shows updated name
    

Then confirm persistence:

- Run `GET /api/user/me/` again → name should still be updated (stored in DB)
    

---

## ⚡ Pro-Tips & Gotchas

> [!PROTIP]  
> Swagger’s “Try it out” + “Execute” is a fast way to validate:

- auth requirements
    
- request/response schema
    
- status codes
    
- real DB changes
    

> [!PROTIP]  
> Use **PATCH** when editing one field (less chance of accidentally overwriting values).

> [!CAUTION]  
> Token auth depends on DB migrations. If tokens aren’t working, check:

- `rest_framework.authtoken` added
    
- migrations applied (restart docker compose)
