# 🔗 `reverse()` — URL resolution

Build a URL from its *name* instead of hard-coding the path.

```python
from django.urls import reverse

RECIPES_URL = reverse("recipe:recipe-list")


def detail_url(recipe_id):
    return reverse("recipe:recipe-detail", args=[recipe_id])
```

**Why every test uses it:** change `/api/recipe/` to `/api/v2/recipe/` and hard-coded paths break in fifty test files. Named URLs don't break at all.

The name has two halves:

```text
recipe : recipe-list
  │          │
  │          └── generated by the router from the registered basename
  └───────────── app_name in the app's urls.py
```

## `NoReverseMatch`

```text
django.urls.exceptions.NoReverseMatch:
'recipe' is not a registered namespace
```

**The cause is almost always a missing `app_name`** — and the error message never says so, which is why this costs people an hour.

```python
# app/recipe/urls.py
app_name = "recipe"        # ← this line

urlpatterns = [path("", include(router.urls))]
```

Other causes:

| Symptom | Cause |
| --- | --- |
| `Reverse for 'recipe-detail' not found` | wrong basename, or the router isn't registered |
| `…with arguments '()' not found` | the URL takes an argument and you passed none |
| namespace not registered | `include()` missing from the project `urls.py` |

Inspect what actually exists:

```bash
docker compose run --rm app sh -c "python manage.py show_urls"
```
