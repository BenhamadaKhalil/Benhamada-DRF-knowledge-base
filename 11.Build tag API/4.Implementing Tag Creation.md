# 🏷️ Implementing Tag Creation When Creating a Recipe

---

## 🎯 Core Concept

In the previous lesson, we wrote **tests** to define the expected behavior when creating recipes with tags.

Now we implement the feature.

The API must support:

1️⃣ **Creating new tags automatically** when they don't exist  
2️⃣ **Reusing existing tags** when they already exist  
3️⃣ **Attaching tags to the recipe** through a Many-To-Many relationship

To achieve this, we implement **custom logic in the serializer's `create()` method**.

---

# 🏗️ Logic Flow

### Request → Object Creation

```

Client Request (POST /recipes)  
│  
▼  
RecipeSerializer  
│  
├─ Extract tags from request  
│  
├─ Create Recipe  
│  
├─ Loop through tags  
│ ├─ get_or_create(tag)  
│ └─ attach to recipe  
│  
▼  
Database  
(Recipe + Tag relations)

````

Example request payload:

```json
{
  "title": "Thai Prawn Curry",
  "time_minutes": 30,
  "price": "2.50",
  "tags": [
    {"name": "Thai"},
    {"name": "Dinner"}
  ]
}
````

Expected result:

- Recipe created
    
- Tags created (if needed)
    
- Tags assigned to recipe
    

---

# 💻 Step 1 — Move the Tag Serializer

The **TagSerializer must appear above the RecipeSerializer**.

Otherwise Python will raise an error because the class would be referenced **before it is defined**.

> [!INFO]  
> Python reads files **top → bottom**.

```python
class TagSerializer(serializers.ModelSerializer):
    """Serializer for tags."""

    class Meta:
        model = Tag
        fields = ['id', 'name']
        read_only_fields = ['id']
```

---

# 💻 Step 2 — Add Nested Tags to RecipeSerializer

Now we embed **tags as a nested serializer**.

> [!CODE]

```python
class RecipeSerializer(serializers.ModelSerializer):
    """Serializer for recipes."""

    tags = TagSerializer(many=True, required=False)

    class Meta:
        model = Recipe
        fields = [
            'id',
            'title',
            'time_minutes',
            'price',
            'link',
            'tags',
        ]
        read_only_fields = ['id']
```

### Key Arguments

|Argument|Meaning|
|---|---|
|`many=True`|Tags are a **list**|
|`required=False`|Tags are **optional**|

---

> [!INFO]  
> By default, **nested serializers are read-only**.

So you can **see tags**, but **cannot create them**.

To enable creation, we must override the serializer's `create()` method.

---

# 💻 Step 3 — Override the `create()` Method

This method adds custom logic for recipe creation.

> [!CODE]

```python
def create(self, validated_data):
    """Create a recipe."""

    # Remove tags from validated_data
    tags = validated_data.pop('tags', [])

    # Create recipe
    recipe = Recipe.objects.create(
        user=self.context['request'].user,
        **validated_data
    )

    # Process tags
    for tag in tags:
        tag_obj, created = Tag.objects.get_or_create(
            user=self.context['request'].user,
            **tag
        )

        recipe.tags.add(tag_obj)

    return recipe
```

---

# 🔎 Step-by-Step Explanation

### 1️⃣ Extract Tags

```python
tags = validated_data.pop('tags', [])
```

> [!INFO]

`pop()` does two things:

- Retrieves the value
    
- **Removes it from the dictionary**
    

Example:

```python
validated_data = {
    "title": "Thai Prawn Curry",
    "tags": [{"name": "Thai"}]
}
```

After `pop()`:

```
tags = [{"name": "Thai"}]

validated_data = {
   "title": "Thai Prawn Curry"
}
```

---

### 2️⃣ Create the Recipe

```python
recipe = Recipe.objects.create(
    user=self.context['request'].user,
    **validated_data
)
```

Important details:

- `self.context['request']` gives access to the **HTTP request**
    
- `.user` gives the **authenticated user**
    

The `**validated_data` syntax **unpacks the dictionary**.

Example:

```python
validated_data = {
   "title": "Thai Prawn Curry",
   "time_minutes": 30
}
```

Becomes:

```python
Recipe.objects.create(
   title="Thai Prawn Curry",
   time_minutes=30
)
```

---

### 3️⃣ Create or Reuse Tags

```python
tag_obj, created = Tag.objects.get_or_create(...)
```

> [!INFO]

`get_or_create()` behavior:

|Case|Result|
|---|---|
|Tag exists|Return existing tag|
|Tag doesn't exist|Create new tag|

This prevents **duplicate tags** in the database.

---

### 4️⃣ Attach Tags to Recipe

```python
recipe.tags.add(tag_obj)
```

This works because **Recipe.tags is a ManyToMany field**.

So the database relation becomes:

```
Recipe
   │
   ├── Tag: Thai
   └── Tag: Dinner
```

---

### 5️⃣ Return the Created Object

```python
return recipe
```

> [!CAUTION]

The serializer **must return the object**, otherwise DRF will fail.

---

# ⚡ Pro Tips & Shortcuts

---

> [!INFO] Use `get_or_create()` to Prevent Duplicates

This is one of the most common **Django ORM patterns**.

```python
obj, created = Model.objects.get_or_create(...)
```

- `obj` → retrieved or created object
    
- `created` → boolean flag
    

---

> [!INFO] Why Use `**tag` Instead of `name=tag["name"]`

Instead of:

```python
Tag.objects.get_or_create(name=tag['name'])
```

We use:

```python
Tag.objects.get_or_create(**tag)
```

This **future-proofs the code**.

If later the tag model becomes:

```
Tag
 - name
 - color
 - category
```

The serializer **still works without modification**.

---

> [!INFO] Accessing Request Inside a Serializer

Serializers don't automatically know the request.

But DRF passes it via:

```python
self.context
```

Example:

```python
self.context['request'].user
```
