# 🔄 Updating Recipe Tags via API (Test Implementation)

---

# 🎯 Core Concept

After implementing **tag creation during recipe creation**, the next feature is **updating the tags assigned to a recipe**.

This includes three scenarios:

1️⃣ **Create a new tag during update** if it doesn't exist  
2️⃣ **Assign an existing tag** when updating  
3️⃣ **Clear all tags** from a recipe

Before implementing the logic, we again follow **Test-Driven Development (TDD)** by writing tests that define the expected behavior.

> [!INFO]
Django REST Framework **does not support writable nested fields by default**.  
Therefore, these tests will initially **fail**, and we will later implement a custom `update()` method.

---

# 🏗️ Logic Flow

### Updating Tags

```

PATCH /recipes/{id}/  
│  
▼  
RecipeSerializer  
│  
▼  
Update Tag Logic  
│  
├─ Create new tags if needed  
├─ Assign existing tags  
└─ Remove old tags if replaced  
▼  
Database Update

````

Example request:

```json
PATCH /api/recipes/5/

{
  "tags": [
    {"name": "Lunch"}
  ]
}
````

Expected behavior:

- Replace current tags
    
- Create tag if it doesn't exist
    
- Assign it to the recipe

# 🧪 Test 1 — Create Tag When Updating Recipe

This test ensures that **new tags are automatically created during an update**.

---

## 💻 Test Implementation

> [!CODE]

```python
def test_create_tag_on_update(self):
    """Test creating a tag when updating a recipe"""

    recipe = create_recipe(user=self.user)

    payload = {
        'tags': [{'name': 'Lunch'}]
    }

    url = detail_url(recipe.id)

    res = self.client.patch(url, payload, format='json')

    self.assertEqual(res.status_code, status.HTTP_200_OK)

    new_tag = Tag.objects.get(
        user=self.user,
        name='Lunch'
    )

    self.assertIn(new_tag, recipe.tags.all())
```

---

### 🔎 What This Test Verifies

✔ PATCH request works  
✔ New tag is created in the database  
✔ Tag is assigned to the recipe

---

> [!INFO]  
> This uses **HTTP PATCH**, which means **partial update**.

Only the fields in the payload are modified.

# 🧪 Test 2 — Assign Existing Tag During Update

This test verifies that an **existing tag is correctly assigned** to the recipe.

---

## 💻 Test Implementation

```python
def test_update_recipe_assign_tag(self):
    """Test assigning an existing tag when updating a recipe"""

    tag_breakfast = Tag.objects.create(
        user=self.user,
        name='Breakfast'
    )

    recipe = create_recipe(user=self.user)
    recipe.tags.add(tag_breakfast)

    tag_lunch = Tag.objects.create(
        user=self.user,
        name='Lunch'
    )

    payload = {
        'tags': [{'name': 'Lunch'}]
    }

    url = detail_url(recipe.id)

    res = self.client.patch(url, payload, format='json')

    self.assertEqual(res.status_code, status.HTTP_200_OK)

    self.assertIn(tag_lunch, recipe.tags.all())
    self.assertNotIn(tag_breakfast, recipe.tags.all())
```

---

### 🔎 Expected Behavior

Initial state:

```
Recipe
 └── Breakfast
```

After update:

```
Recipe
 └── Lunch
```

✔ Old tag removed  
✔ New tag assigned

# 🧪 Test 3 — Clearing Recipe Tags

Users may want to **remove all tags from a recipe**.

This test ensures that passing an **empty list** clears them.

---

## 💻 Test Implementation

```python
def test_clear_recipe_tags(self):
    """Test clearing tags from a recipe"""

    tag = Tag.objects.create(
        user=self.user,
        name='Dessert'
    )

    recipe = create_recipe(user=self.user)
    recipe.tags.add(tag)

    payload = {'tags': []}

    url = detail_url(recipe.id)

    res = self.client.patch(url, payload, format='json')

    self.assertEqual(res.status_code, status.HTTP_200_OK)

    self.assertEqual(recipe.tags.count(), 0)
```

---

### 🔎 Expected Behavior

Initial state:

```
Recipe
 └── Dessert
```

Request:

```json
{
  "tags": []
}
```

Result:

```
Recipe
 (no tags)
```

# ⚡ Pro Tips & Shortcuts

---

> [!INFO] No `refresh_from_db()` Needed for Many-to-Many

Normally, when updating models in tests you must refresh the object:

```python
recipe.refresh_from_db()
```

But for **ManyToMany fields**, this is unnecessary.

Why?

Because:

```python
recipe.tags.all()
```

always performs a **fresh database query**.

---

> [!INFO] PATCH vs PUT

|Method|Behavior|
|---|---|
|PUT|Replace the entire object|
|PATCH|Update only specified fields|

Example:

```python
self.client.patch(url, payload)
```

---

> [!CAUTION] Nested Serializers Are Read-Only by Default

When running the tests, you will see the error:

```
The .update() method does not support writable nested fields by default
```

This happens because DRF **does not allow nested writes automatically**.

To fix this, we must **override the serializer `update()` method**.

That will be implemented in the next step.
