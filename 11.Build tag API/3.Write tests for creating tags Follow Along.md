# 🏷️ Creating Tags When Creating Recipes (DRF Nested Objects)

---

## 🎯 Core Concept

When creating a **Recipe** through the API, the user should also be able to send **tags** in the same request.

Two cases must be handled:

1️⃣ **Tag does NOT exist** → create it and assign it to the recipe.  
2️⃣ **Tag already exists** → reuse it and attach it to the recipe.

This prevents **duplicate tags** and keeps the database clean.

Before implementing the feature, we follow **Test-Driven Development (TDD)** by writing tests that define the expected behavior.

---

## 🏗️ Logic Flow

### API Data Flow

```

Client Request  
│  
▼  
Recipe API Endpoint  
│  
▼  
Recipe ViewSet  
│  
▼  
Recipe Serializer  
│  
▼  
Tag Handling Logic  
│  
▼  
Database  
(Recipe + Tag relations)

````

Example request:

```json
POST /api/recipes/

{
  "title": "Thai Prawn Curry",
  "time_minutes": 30,
  "price": "2.50",
  "tags": [
    {"name": "Thai"},
    {"name": "Dinner"}
  ]
}
````

Expected result:

- Recipe created
    
- Two tags created
    
- Tags assigned to the recipe

# 🧪 Test Case 1 — Creating Recipe With New Tags

We test that:

- The API creates the recipe
    
- The tags are created
    
- The tags are attached to the recipe
    

---

## 💻 Test Implementation

> [!CODE] Import the Tag model

```python
from core.models import (
    Recipe,
    Tag,
)
```

---

> [!CODE] Test: create recipe with new tags

```python
def test_create_recipe_with_new_tags(self):
    """Test creating a recipe with new tags"""

    payload = {
        'title': 'Thai Prawn Curry',
        'time_minutes': 30,
        'price': Decimal('2.50'),
        'tags': [
            {'name': 'Thai'},
            {'name': 'Dinner'},
        ],
    }

    res = self.client.post(RECIPES_URL, payload, format='json')

    self.assertEqual(res.status_code, status.HTTP_201_CREATED)

    recipes = Recipe.objects.filter(user=self.user)
    self.assertEqual(recipes.count(), 1)

    recipe = recipes[0]

    # recipe should have two tags
    self.assertEqual(recipe.tags.count(), 2)

    for tag in payload['tags']:
        exists = recipe.tags.filter(
            name=tag['name'],
            user=self.user,
        ).exists()

        self.assertTrue(exists)
```

---

### 🔎 What This Test Verifies

✔ Recipe successfully created  
✔ Two tags exist in the database  
✔ Tags belong to the authenticated user  
✔ Tags are attached to the recipe

# 🧪 Test Case 2 — Using Existing Tags

Now we test the **duplicate prevention logic**.

Scenario:

- A tag **already exists**
    
- The user creates a recipe using that tag
    
- The API should **reuse the existing tag**, not create another one.
    

---

## 💻 Test Implementation

```python
def test_create_recipe_with_existing_tags(self):
    """Test creating a recipe with existing tag"""

    tag_indian = Tag.objects.create(
        user=self.user,
        name='Indian'
    )

    payload = {
        'title': 'Pongal',
        'time_minutes': 60,
        'price': Decimal('4.50'),
        'tags': [
            {'name': 'Indian'},
            {'name': 'Breakfast'},
        ],
    }

    res = self.client.post(RECIPES_URL, payload, format='json')

    self.assertEqual(res.status_code, status.HTTP_201_CREATED)

    recipes = Recipe.objects.filter(user=self.user)
    self.assertEqual(recipes.count(), 1)

    recipe = recipes[0]

    self.assertEqual(recipe.tags.count(), 2)

    # ensure existing tag reused
    self.assertIn(tag_indian, recipe.tags.all())

    for tag in payload['tags']:
        exists = recipe.tags.filter(
            name=tag['name'],
            user=self.user,
        ).exists()

        self.assertTrue(exists)
```

## ⚡ Pro Tips & Shortcuts

> [!INFO] Always Test Nested Object Behavior  
> Nested serializers often cause bugs. Tests ensure the API correctly handles:

- creation
    
- association
    
- deduplication
    

---

> [!CAUTION] Prevent Generic Errors in Tests

This assertion prevents unclear errors:

```python
self.assertEqual(recipes.count(), 1)
```

Without it, accessing:

```python
recipe = recipes[0]
```

might cause a confusing **IndexError** instead of a clear test failure.

---

> [!INFO] Always Send Nested Data as JSON

```python
res = self.client.post(URL, payload, format='json')
```

This ensures DRF correctly parses **nested dictionaries**.
