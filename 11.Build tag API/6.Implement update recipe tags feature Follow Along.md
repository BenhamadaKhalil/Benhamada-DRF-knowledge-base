# 🎯 What We Are Implementing

We want the API to support:

```
PATCH /api/recipes/{id}/
```

Example request:

```json
{
  "tags": [
    {"name": "Lunch"}
  ]
}
```

The API must:

1️⃣ Replace existing tags  
2️⃣ Create tags if they don't exist  
3️⃣ Assign them to the recipe  
4️⃣ Allow clearing tags (`"tags": []`)

---

# 🧠 The Problem

By default, **Django REST Framework cannot update nested objects** like this:

```
Recipe
  └── Tags (ManyToMany)
```

So we must **override the serializer `update()` method**.

---

# 🧩 Final Serializer Structure

Your `RecipeSerializer` now has **three important methods**:

```
RecipeSerializer
 ├── _get_or_create_tags()
 ├── create()
 └── update()
```

Each has a different job.

---

# 1️⃣ `_get_or_create_tags()` (helper function)

This function **loops through tags** and:

- finds them if they exist
    
- creates them if they don't
    
- attaches them to the recipe
    

```python
def _get_or_create_tags(self, tags, recipe):
    """Handle getting or creating tags as needed."""
    auth_user = self.context['request'].user

    for tag in tags:
        tag_obj, created = Tag.objects.get_or_create(
            user=auth_user,
            **tag
        )
        recipe.tags.add(tag_obj)
```

### What happens inside

Example request:

```json
"tags": [
  {"name": "Lunch"},
  {"name": "Dinner"}
]
```

Loop result:

```
1 → check Lunch
2 → create if missing
3 → add to recipe
```

---

# 2️⃣ `create()` (Recipe creation)

When creating a recipe:

```python
POST /recipes/
```

We separate the tags first.

```python
def create(self, validated_data):
    tags = validated_data.pop('tags', [])

    recipe = Recipe.objects.create(**validated_data)

    self._get_or_create_tags(tags, recipe)

    return recipe
```

### Why `pop()`?

Because `Recipe.objects.create()` **does not understand nested tags**.

So we remove them first.

```
validated_data before pop

{
title
price
time_minutes
tags
}

after pop

{
title
price
time_minutes
}
```

# 3️⃣ `update()` (Recipe update)

This is the **new part of the lesson**.

```python
def update(self, instance, validated_data):
    tags = validated_data.pop('tags', None)

    if tags is not None:
        instance.tags.clear()
        self._get_or_create_tags(tags, instance)

    for attr, value in validated_data.items():
        setattr(instance, attr, value)

    instance.save()
    return instance
```

# 🔥 Why This Condition Is Important

```python
if tags is not None:
```

This allows **two behaviors**.

---

### Case 1 — Update tags

Request:

```json
{
 "tags": [{"name":"Lunch"}]
}
```

Tags updated.

---

### Case 2 — Clear tags

Request:

```json
{
 "tags": []
}
```

Result:

```
Recipe
(no tags)
```

---

### Case 3 — Do NOT modify tags

Request:

```json
{
 "title": "New title"
}
```

Because `"tags"` is missing:

```
tags = None
```

This block is skipped:

```
if tags is not None:
```

So **tags remain unchanged**.

# ⚠️ Why We Refactored Code

Originally, this logic was duplicated:

```
create()
update()
```

So we moved it into:

```
_get_or_create_tags()
```

Now both methods reuse it.

---

# 🧠 The Big Picture

```
RecipeSerializer

create()
   │
   └─ _get_or_create_tags()

update()
   │
   ├─ clear existing tags
   └─ _get_or_create_tags()
```

This is **cleaner architecture**.
