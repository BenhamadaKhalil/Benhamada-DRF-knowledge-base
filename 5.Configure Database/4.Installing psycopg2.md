# Django – Installing psycopg2 in Docker (Alpine)

## 📌 Lesson Goal

Install the PostgreSQL adapter (`psycopg2`) inside the Docker environment properly.

Since we are using:
- Alpine Linux base image
- Compiled version of psycopg2 (not binary)

We must install system-level dependencies first.

---

# 🐳 Step 1 – Update Dockerfile

Open:

```
Dockerfile
```

We will install:
- PostgreSQL client (needed at runtime)
- Build dependencies (needed only to compile psycopg2)

---

## 🔹 Install PostgreSQL Client (Required at Runtime)

Add after upgrading pip:

```dockerfile
RUN apk add --update --no-cache postgresql-client
```

### Why?
`psycopg2` needs PostgreSQL client libraries to communicate with the database.

This package must remain in the final image.

---

## 🔹 Install Build Dependencies (Temporary)

```dockerfile
RUN apk add --update --no-cache --virtual .tmp-build-deps \
    build-base \
    postgresql-dev \
    musl-dev
```

### What this does:

- `--virtual .tmp-build-deps`
  - Creates a temporary package group
  - Makes it easy to remove later

Installed packages:
- `build-base` → C compiler tools
- `postgresql-dev` → Postgres headers
- `musl-dev` → C standard library headers

These are needed to compile `psycopg2` from source.

---

# 🧠 Why Not Keep Them?

They are only required to INSTALL psycopg2.

After installation:
- They are no longer needed
- Keeping them increases image size
- Adds unnecessary packages to production

---

## 🔹 Remove Build Dependencies

After installing Python requirements:

```dockerfile
RUN apk del .tmp-build-deps
```

This removes:
- build-base
- postgresql-dev
- musl-dev

Keeps image:
- Smaller
- Cleaner
- Production-ready

---

# 📦 Step 2 – Add psycopg2 to requirements.txt

Open:

```
requirements.txt
```

Add:

```txt
psycopg2>=2.8.6,<2.9
```

### Why version range?

- Prevents breaking changes
- Keeps compatibility stable
- Allows minor patch updates

---

# 🔁 Step 3 – Rebuild Docker Image

Stop containers:

```bash
docker-compose down
```

Rebuild image:

```bash
docker-compose build
```

If build completes successfully:
✅ psycopg2 installed correctly  
✅ Dependencies configured correctly  

---

# 🧠 What Actually Happened (Deep Understanding)

Docker build process:

1. Install PostgreSQL client
2. Install build dependencies
3. Install Python requirements (including psycopg2)
4. Remove build dependencies
5. Final image contains:
   - Django
   - psycopg2
   - PostgreSQL client
   - NO unnecessary build tools

This is production-grade Docker optimization.

---

# 🏗️ Final Architecture of Docker Image

```
Final Container Contains:
- Python
- Django
- psycopg2
- PostgreSQL client
- App source code

Removed:
- Compiler tools
- Dev headers
```

---

# 🔥 Key Takeaways

- psycopg2 requires system dependencies when compiled from source
- Alpine package names differ from standard Linux
- Use `--virtual` to group build deps
- Always remove build deps after installing
- Rebuild Docker after changing Dockerfile or requirements

---

# 🧠 Professional Insight

This pattern (install build deps → install requirements → remove build deps)
