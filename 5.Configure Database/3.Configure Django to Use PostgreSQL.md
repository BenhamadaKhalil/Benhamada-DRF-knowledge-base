# Django – Configure Django to Use PostgreSQL (Docker Setup)

## 📌 Lesson Goal
Set up Django so it can connect to the PostgreSQL database running in Docker Compose.

1) Configure Django database settings  
2) Install OS-level dependencies (inside Docker image) needed by the DB adapter  
3) Add the PostgreSQL adapter to `requirements.txt`

---

# ✅ What Django Needs to Connect to a Database

Django’s DB connection is configured in `settings.py` using these values:

- **ENGINE**: database backend type (PostgreSQL)
- **HOST**: hostname / IP / domain of the database  
  - In Docker Compose: host is typically the service name (`db`)
- **PORT**: Postgres default port = `5432` (usually left as default)
- **NAME**: the database name (inside Postgres)
- **USER** + **PASSWORD**: application credentials for DB authentication

These are all placed under the `DATABASES` setting in `settings.py`.

---

# 🌍 Use Environment Variables for Configuration

Instead of hardcoding values inside `settings.py`, we pull them from **environment variables**.

Why this is good:
- Docker containers are commonly configured through env vars
- Works in development and production
- Central place to configure your app (change config without changing code)

Example pattern in Python:

```python id="w2c2z6"
import os

db_host = os.environ.get("DB_HOST")
```

We’ll use `os.environ.get(...)` for all DB-related values.

# 🔌 PostgreSQL Adapter: `psycopg2`

To connect Python/Django to PostgreSQL, we need a **database adapter**.

Most common adapter:
- **psycopg2** (recommended + supported by Django)

## Installation Options

### Option A: `psycopg2-binary`
- Pre-compiled binary
- Easy install
- OK for local development
- ❌ Not recommended for production (less optimized for target OS)

### Option B: `psycopg2` (compiled from source)
- Compiled for the OS you’re running on
- ✅ Better performance & reliability
- ❗ Requires build dependencies (C compiler + Postgres dev libraries)

Since we are using **Docker**, we can reliably install those dependencies in the container → so using **psycopg2 (non-binary)** becomes easier and consistent.

---

# 🧱 Build Dependencies Needed for `psycopg2` (inside Docker)

When compiling from source, `psycopg2` needs system packages.

General dependencies (from docs) include:
- C compiler
- Python dev headers
- Postgres client/dev libraries

## Alpine-Specific Package Names
Because our Docker base image is **Alpine**, package names differ.

Equivalent Alpine packages mentioned:
- `postgresql-client`
- `build-base`
- `postgresql-dev`
- `musl-dev`

The instructor mentions finding these via trial-and-error + online research (StackOverflow etc.).

---

# 🧼 Docker Best Practice: Remove Build Dependencies

Most build dependencies are only needed to **install** `psycopg2`, not to **run** your app.

Best practice:
- Install build deps
- Install Python requirements (including psycopg2)
- Remove build deps to keep the image small

This keeps your Docker image:
- leaner
- faster to ship
- more secure (fewer packages installed)

---

# ✅ Key Takeaways

- Django DB config lives in `settings.py` under `DATABASES`
- Use environment variables for DB settings (dev + prod friendly)
- Django uses `psycopg2` to connect to PostgreSQL
- `psycopg2-binary` is easy but not ideal for production
- In Docker (Alpine), we install system deps to compile `psycopg2`
- Clean up build deps after installation to keep image lightweight
