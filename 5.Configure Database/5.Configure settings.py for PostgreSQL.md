# Django – Configure settings.py for PostgreSQL

## 📌 Lesson Goal

Now that `psycopg2` is installed, configure Django to use PostgreSQL instead of the default SQLite database.

---

# 🗂 Step 1 – Open settings.py

Path:

```
app/app/settings.py
```

Scroll to the `DATABASES` section.

By default, Django includes SQLite configuration:

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}
```

We are NOT using SQLite anymore.

---

# 🔄 Step 2 – Replace SQLite with PostgreSQL

Update the `DATABASES` setting to:

```python
import os

DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'HOST': os.environ.get('DB_HOST'),
        'NAME': os.environ.get('DB_NAME'),
        'USER': os.environ.get('DB_USER'),
        'PASSWORD': os.environ.get('DB_PASS'),
    }
}
```

---

# 🧠 Explanation of Each Setting

## ENGINE
```python
'django.db.backends.postgresql'
```
Tells Django to use the PostgreSQL backend.

This string comes from official Django documentation.

---

## HOST
```python
os.environ.get('DB_HOST')
```
- The hostname of the database
- In Docker Compose → this is `db`
- Pulled from environment variable

---

## NAME
```python
os.environ.get('DB_NAME')
```
The name of the database inside Postgres (e.g., `devdb`).

---

## USER
```python
os.environ.get('DB_USER')
```
Database username created in Docker.

---

## PASSWORD
```python
os.environ.get('DB_PASS')
```
Database password.

---

# 🌍 Why Use Environment Variables?

Because we defined these in `docker-compose.yml`:

```yaml
environment:
  - DB_HOST=db
  - DB_NAME=devdb
  - DB_USER=devuser
  - DB_PASS=changeme
```

Django reads them dynamically.

### Advantages:
- No hardcoded credentials
- Works in development and production
- Easy to change configuration
- Follows Docker best practices

---

# 🧹 Step 3 – Remove SQLite File

Delete:

```
db.sqlite3
```

Why?

We are no longer using SQLite.
Keeping it creates confusion.

---

# 🏗️ Final Connection Flow

```
docker-compose.yml
      ↓
Environment Variables
      ↓
settings.py (os.environ.get)
      ↓
Django connects using psycopg2
      ↓
PostgreSQL container
```

---

# 🔥 Key Takeaways

- Django uses `DATABASES` dict for DB configuration
- PostgreSQL backend must be explicitly defined
- Service name `db` becomes the hostname
- Environment variables prevent hardcoding credentials
- SQLite is removed when switching to Postgres
