## ✅ Goal of this lesson

Add a feature so when a user registers, their **email gets normalized** (mainly the **domain part becomes lowercase**) using Django’s built-in helper: `BaseUserManager.normalize_email()`.

---

# 1) Add the unit test: normalize emails

File: `core/tests/test_models.py`

Add this **new test method** inside your existing `ModelTests(TestCase)` class:

```python
def test_new_user_email_normalized(self):
    """Test email is normalized for new users."""
    sample_emails = [
        ['test1@example.com', 'test1@example.com'],
        ['Test2@Example.com', 'Test2@example.com'],
        ['test3@EXAMPLE.com', 'test3@example.com'],
        ['test4@example.COM', 'test4@example.com'],
    ]

    for email, expected in sample_emails:
        user = get_user_model().objects.create_user(
            email=email,
            password='sample123',
        )
        self.assertEqual(user.email, expected)
```

### Why this test looks like that

- We test multiple variations (uppercase domain, mixed case, etc.)
    
- The **local part** (before `@`) is _not forced_ to lowercase (email spec allows case sensitivity there)
    
- The **domain part** should be lowercase
    

---

# 2) Implement the feature: normalize email in `create_user`

File: `core/models.py` in your `UserManager.create_user`

Change your `user = self.model(...)` line to normalize the email:

```python
def create_user(self, email, password=None, **extra_fields):
    """Create, save and return a new user."""
    user = self.model(email=self.normalize_email(email), **extra_fields)
    user.set_password(password)
    user.save(using=self._db)
    return user
```

That’s it ✅

`normalize_email()` comes from `BaseUserManager` (which your `UserManager` inherits from).

## Common mistakes

- Writing `self.normalize_email` but forgetting `(email)`
    
- Normalizing after saving (too late)
    
- Wrong indentation in the test loop (test silently won’t run or will error)
