# 🧪 Writing Unit Tests for Custom User Model

Before implementing the custom user model, we write a **unit test first**.

This follows:

> 🧠 TDD – Test Driven Development  
> Write the test → Watch it fail → Implement the code → Make it pass

---

# 📁 Test File Structure

Location:

```
core/tests/test_models.py
```

This file will contain all tests related to models in the `core` app.

# 🧠 Importing Dependencies

```python
from django.test import TestCase
from django.contrib.auth import get_user_model
```

### Why use `get_user_model()`?

Instead of importing directly:

```python
from core.models import User
```

We use:

```python
get_user_model()
```

Because:

- It always returns the currently configured user model
    
- Future-proof
    
- Works even if user model changes
    

Best Practice:

> Always use `get_user_model()` when referencing the user model.

---

# 🧪 First Test: Create User with Email

```python
class ModelTests(TestCase):

    def test_create_user_with_email_successful(self):
        email = 'test@example.com'
        password = 'testpass123'

        user = get_user_model().objects.create_user(
            email=email,
            password=password,
        )

        self.assertEqual(user.email, email)
        self.assertTrue(user.check_password(password))
```

---

# 🧠 What This Test Does

### Step 1 – Setup Test Data

```python
email = 'test@example.com'
password = 'testpass123'
```

💡 Use `example.com` domain  
It is reserved for testing.

---

### Step 2 – Create User

```python
get_user_model().objects.create_user()
```

- `objects` → manager
    
- `create_user()` → method we will implement
    

---

### Step 3 – Assertions

```python
self.assertEqual(user.email, email)
```

Checks email was stored correctly.

---

### Step 4 – Password Check

```python
self.assertTrue(user.check_password(password))
```

Important:

We do NOT do:

```python
self.assertEqual(user.password, password)
```

Why?

Because password is hashed.

Instead we use:

```python
check_password()
```

Which verifies hashed password correctly.

---

# 🔐 Why Password Hashing Matters

Stored in DB like:

```
pbkdf2_sha256$...
```

Not:

```
testpass123
```

Always use Django’s built-in hashing.

# 🧨 Running the Test

Command:

```bash
docker compose run --rm app sh -c "python manage.py test"
```

Result:

❌ Test fails

Error:

```
TypeError: missing required positional argument 'username'
```

---

# 🤔 Why Does It Fail?

Because:

We haven’t implemented our custom user model yet.

Django is still using:

```
Default User Model
```

And default model requires:

```
username
```

But our test uses:

```
email only
```

So failure is expected.

---

# 🧠 This Is Good

Failure = success in TDD.

It proves:

- Our test is correct
    
- Default model is still active
    
- Once we override it → test will pass
    

---

|---|---|

|check_password()|Secure verification|
|Expected failure|Confirms override needed|
