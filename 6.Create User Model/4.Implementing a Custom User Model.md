# 👤 Implementing a Custom User Model (Email Login) + Fixing Migration History

This lesson is the **implementation step** after the failing test. We create:

- A custom `User` model (email instead of username)
    
- A custom `UserManager` (handles password hashing + user creation)
    
- `AUTH_USER_MODEL` config in settings
    
- Migrations + fix “inconsistent migration history” by resetting DB volume

---

## 2) Create `UserManager`

You define the manager **above** the model (common style).

```python
class UserManager(BaseUserManager):
    """Manager for users."""

    def create_user(self, email, password=None, **extra_fields):
        """Create, save and return a new user."""
        user = self.model(email=email, **extra_fields)
        user.set_password(password)  # hashes password
        user.save(using=self._db)    # supports multiple DBs
        return user
```

### Key idea

- `set_password()` ✅ hashes password
    
- `**extra_fields` ✅ lets you pass other fields like `name` without modifying method signature later
    
- `using=self._db` ✅ best practice for multi-database support
    

> 🔥 Common bug: typo in `extra_fields` (must match exactly). If you wrote `extra_field` you’ll get: **extra_fields is not defined**.

---

## 3) Create `User` Model

```python
class User(AbstractBaseUser, PermissionsMixin):
    """User in the system."""

    email = models.EmailField(max_length=255, unique=True)
    name = models.CharField(max_length=255)
    is_active = models.BooleanField(default=True)
    is_staff = models.BooleanField(default=False)

    objects = UserManager()

    USERNAME_FIELD = 'email'
```

### Why these fields?

- `email` unique ✅ required because it’s login identifier
    
- `is_active` ✅ allows disabling accounts without deleting
    
- `is_staff` ✅ controls access to Django admin
    

### Critical line

`USERNAME_FIELD = 'email'` ✅ replaces default username login.

## 4) `settings.py` — Activate Custom User Model

At the bottom:

```python
AUTH_USER_MODEL = 'core.User'
```

⚠️ Must be spelled exactly. Also ensure `core` is already in `INSTALLED_APPS`.

## 7) Fix: “Inconsistent migration history”

This happens because you already migrated using the **default Django user model**, then you changed to a custom user model.

✅ Fix (reset DB volume):

1. List volumes:
    

```bash
docker volume ls
```

2. Stop containers:
    

```bash
docker compose down
```

3. Remove dev DB volume (the one like `...dev-db-data`):
    

```bash
docker volume rm <VOLUME_NAME>
```

4. Re-run migrations:
    

```bash
docker compose run --rm app sh -c "python manage.py wait_for_db && python manage.py migrate"
```
