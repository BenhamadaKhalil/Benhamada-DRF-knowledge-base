# 👤 Custom User Model in Django

## 🎯 Why Create a Custom User Model?

Django comes with a **built-in authentication system**, including:

- Registration
    
- Login
    
- Password hashing
    
- Authentication system
    
- Admin integration
    
- Permissions system
    

The default user model works fine… but it has limitations.

---

## ❌ Problems with Default Django User

- Uses **username** instead of **email** by default
    
- Hard to customize later
    
- Painful to change after migrations are created
    
- Not future-proof
    

💡 Best Practice:

> Always create a custom user model at the start of a project — even if you don’t need customization yet.

This avoids serious migration headaches later.

---

# 🧠 What We’re Going to Do

We will:

1. Create our own `User` model
    
2. Base it on Django’s abstract classes
    
3. Create a custom manager
    
4. Configure Django to use it
    
5. Run migrations
    

---

# 🏗️ Django Authentication Architecture

Django’s auth system is built on models.

The default user model:

- Stores user data
    
- Handles password hashing
    
- Integrates with admin
    
- Works with permission system
    

We’re going to replace it with our own.

---

# 🧩 Core Classes We Will Use

## 1️⃣ `AbstractBaseUser`

Provides:

- Password handling
    
- Authentication logic
    

Does NOT provide:

- Fields like username or email
    

👉 We define our own fields.

---

## 2️⃣ `PermissionsMixin`

Provides:

- is_superuser
    
- groups
    
- permissions
    
- Permission system integration
    

Required for:

- Django Admin compatibility
    
- Permission-based access control
    

---

# 🏗️ How Custom User Model Works

### Step 1: Create Custom User Model

```python
class User(AbstractBaseUser, PermissionsMixin):
```

This becomes the new auth model.

---

### Step 2: Create Custom Manager

Manager is responsible for:

- Creating users
    
- Creating superusers
    
- Handling CLI user creation
    
- Managing required fields
    

Without a custom manager → Django will break.

---

### Step 3: Set `AUTH_USER_MODEL` in settings.py

```python
AUTH_USER_MODEL = 'core.User'
```

⚠️ Must be done BEFORE running migrations.

---

### Step 4: Run Migrations

```bash
python manage.py makemigrations
python manage.py migrate
```

---

# 🚨 Common Mistakes (Very Important)

## ❌ Running Migrations Before Setting Custom User

If you:

- Run migrations
    
- Then decide to create a custom user model
    

You will get migration conflicts and serious errors.

Fix = Reset migrations + DB (annoying).

---

## ❌ Typos in `AUTH_USER_MODEL`

Wrong:

```python
AUTH_USER_MODEL = 'User'
```

Correct:

```python
AUTH_USER_MODEL = 'core.User'
```

It must include:

```
app_name.ModelName
```

---

## ❌ Indentation Errors in Manager

Custom manager methods must be properly indented:

```python
class UserManager(BaseUserManager):

    def create_user(self, email, password=None):
        ...
```

Bad indentation → weird Django errors.
