# 🗂 1️⃣ Where the GitHub Actions Config Lives

GitHub Actions needs a config file inside your project.

The exact path must be:

```
.github/workflows/checks.yml
```

Important details:

- The folder **must** be `.github`
    
- Inside it → `workflows`
    
- The file can be named anything (`checks.yml`, `ci.yml`, etc.)
    
- It **must** end with `.yml` or `.yaml`
    

That file defines:

- Triggers
    
- Jobs
    
- Steps (linting, tests, etc.)
    

---

# 🔄 2️⃣ What We’ll Configure in That File

Inside that YAML file we will:

1. Define a **trigger** (on push)
    
2. Define a **job**
    
3. Add steps to:
    
    - Build Docker image
        
    - Run Flake8
        
    - Run Django tests
        
4. Authenticate with Docker Hub
    

That last one is very important 👇

---

# 🐳 3️⃣ Why Docker Hub Authentication Matters

When GitHub Actions runs your workflow:

- It builds your Docker image
    
- That image is based on a base image (like `python:3.9-alpine`)
    
- That base image is pulled from Docker Hub
    

And here’s the issue…

---

## 🚫 Docker Hub Rate Limits

Docker Hub limits how many images can be pulled.

### Anonymous users:

- 100 pulls per 6 hours
    
- Limited by IP address
    

### Authenticated users:

- 200 pulls per 6 hours
    
- Limited by account
    

Now here’s the problem:

GitHub Actions runs on shared infrastructure.

That means:

- Thousands of users share the same IP
    
- The anonymous 100-pull limit gets used up FAST
    
- Your workflow may fail randomly
    

That’s super annoying.

---

# ✅ Solution: Authenticate with Docker Hub

When we authenticate:

- We use our Docker Hub account
    
- We get our own 200 pulls per 6 hours
    
- No shared IP problems
    
- Much more stable CI
    

---

# 🔐 4️⃣ How Authentication Works

We do NOT hardcode credentials in the YAML file.

Instead we use:

> GitHub Secrets

Secrets are:

- Encrypted variables stored in GitHub
    
- Hidden from the public
    
- Only available inside workflows
    
- Automatically decrypted during job execution
    

We previously created:

- `DOCKERHUB_USER`
    
- `DOCKERHUB_TOKEN`
    

Those will be used inside the workflow.

---

# 🧠 Big Picture Flow

When you push code:

```
Push → GitHub Actions starts
     → Login to Docker Hub (using secret)
     → Pull base image
     → Build Docker image
     → Run lint
     → Run tests
     → Green ✔ or Red ❌
```
