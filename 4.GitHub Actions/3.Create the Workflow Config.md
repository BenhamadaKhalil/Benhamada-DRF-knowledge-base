## ✅ GitHub Actions: Create the Workflow Config

### 1) Create the correct folders/files

GitHub Actions only detects workflows if they are in this exact location:

```
.github/workflows/checks.yml
```

Steps:

- In the **root** of the project (NOT inside `app/`)
    
    - Create folder: `.github`
        
    - Inside it create folder: `workflows`
        
    - Inside workflows create file: `checks.yml`
        

> File name can be anything, but it must be inside `workflows/` and end with `.yml` or `.yaml`.

---

## 2) Start the YAML workflow file

Common YAML start:

- `---` (optional, but nice to indicate YAML)
    

Then define workflow metadata:

```yml
name: Checks
on: [push]
```

- `name`: shown in GitHub Actions UI
    
- `on: [push]`: triggers workflow on every push
    

---

## 3) Define a Job (Test + Lint)

Jobs are tasks run by GitHub Actions. Example job:

```yml
jobs:
  test-lint:
    name: Test and Lint
    runs-on: ubuntu-20.04
```

Explanation:

- `test-lint`: job **id** (used internally if referencing other jobs)
    
- `name`: human-friendly display name
    
- `runs-on`: runner OS (Ubuntu is common + cheaper than Windows runners)
    

---

## 4) Steps: What the job actually does

A job runs **steps in order**. If any step fails (exit code ≠ 0), the job fails.

### Step A: Login to Docker Hub (avoid rate limits)

Use a prebuilt action:

```yml
- name: Login to Docker Hub
  uses: docker/login-action@v1
  with:
    username: ${{ secrets.DOCKERHUB_USER }}
    password: ${{ secrets.DOCKERHUB_TOKEN }}
```

Why:

- GitHub Actions uses shared servers → Docker Hub **rate limits** hit fast for anonymous pulls
    
- Logging in gives you higher limits and more stable builds
    

> These secrets must be created in GitHub repo settings before pushing.

---

### Step B: Checkout repository code

By default, your code is NOT present in the runner unless you checkout.

```yml
- name: Checkout
  uses: actions/checkout@v2
```

---

### Step C: Run tests (via Docker Compose)

Run Django tests inside the container:

```yml
- name: Test
  run: docker-compose run --rm app sh -c "python manage.py test"
```

---

### Step D: Run lint (Flake8 via Docker Compose)

Run Flake8 inside the container:

```yml
- name: Lint
  run: docker-compose run --rm app sh -c "flake8"
```

---

## 5) Full workflow example (final result)

```yml
---
name: Checks
on: [push]

jobs:
  test-lint:
    name: Test and Lint
    runs-on: ubuntu-20.04
    steps:
      - name: Login to Docker Hub
        uses: docker/login-action@v1
        with:
          username: ${{ secrets.DOCKERHUB_USER }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Checkout
        uses: actions/checkout@v2

      - name: Test
        run: docker-compose run --rm app sh -c "python manage.py test"

      - name: Lint
        run: docker-compose run --rm app sh -c "flake8"
```

---

## Key takeaways

- Workflow file must be in `.github/workflows/`
    
- Trigger used: `push`
    
- Runner used: `ubuntu-20.04` (Docker + docker-compose already available)
    
- Steps: Docker Hub login → checkout → tests → lint
    
- Any failing step makes the job fail
