# 🤖 GitHub Actions — Automated Testing & Linting

> 🎯 In this section, we’re setting up **GitHub Actions** to automatically run tasks whenever we push code to GitHub.

This is your first step into **CI (Continuous Integration)** 🔥

---

# 🧠 What is GitHub Actions?

GitHub Actions is an **automation tool built into GitHub**.

It’s similar to:

- Jenkins
    
- GitLab CI/CD
    
- Travis CI
    
- CircleCI
    

But it works **natively inside GitHub**.

---

# ⚙️ What Does It Do?

It allows you to:

- 🔍 Run linting automatically
    
- 🧪 Run unit tests automatically
    
- 🚀 Deploy applications automatically
    
- 📦 Build Docker images automatically
    

All triggered when something happens in your repository.

---

# 🔔 How GitHub Actions Works

It follows this simple logic:

```
Trigger → Job → Result
```

---

## 1️⃣ Trigger

A trigger is an event that happens in your repository.

Examples:

- `push`
    
- `pull_request`
    
- `release`
    
- `schedule`
    

In this course, we use:

```yaml
on: push
```

Meaning:  
👉 Whenever we push code → run automation

---

## 2️⃣ Job

When the trigger activates, GitHub runs a **job**.

In our case, we will:

- 🧹 Run Flake8 linting
    
- 🧪 Run Django unit tests
    

---

## 3️⃣ Result

Each job produces:

- ✅ Success → Green checkmark
    
- ❌ Failure → Red X
    

If it fails:

- You can see logs in GitHub
    
- You can receive email notifications
    
- You fix the issue and push again
