# 👨‍🍳 Implementing Recipe Creation in DRF (Assigning Authenticated User)

---

## 🎯 Core Concept

In the previous step, we created a **test that verifies recipe creation via the API**.  
However, the test failed because the **Recipe model requires a user**, and the API did not assign one during creation.

The solution is to **override the DRF ViewSet creation behavior** so that every new recipe is automatically linked to the **authenticated user** making the request.

> [!INFO]
> Django REST Framework already provides the **create logic automatically** through `ModelViewSet`.  
> We only need to customize **how the object is saved**.

---

## 🏗️ Logic Flow (Object Creation in DRF)

When a client sends a **POST request** to create a recipe, the internal DRF workflow looks like this:

```

Client Request  
│  
▼  
POST /api/recipe/recipes/  
│  
▼  
ModelViewSet.create()  
│  
▼  
Serializer Validation  
│  
▼  
perform_create(serializer) ← we override this  
│  
▼  
serializer.save()  
│  
▼  
Recipe Object Saved (with user)

```

The key extension point is:

```

perform_create()

```

This method lets us **inject custom logic during object creation**.

## 💻 Implementation

### 📂 File Location

```

app/  
└── recipe/  
└── views.py

````

---

### 🧠 Override `perform_create()`

```python
class RecipeViewSet(viewsets.ModelViewSet):
    """View for managing recipe APIs."""

    serializer_class = serializers.RecipeDetailSerializer
    queryset = Recipe.objects.all()

    authentication_classes = [TokenAuthentication]
    permission_classes = [IsAuthenticated]


    def perform_create(self, serializer):
        """Create a new recipe and assign it to the authenticated user."""
        serializer.save(user=self.request.user)
````

---

### 🔍 Code Breakdown

#### 1️⃣ Method Signature

```python
def perform_create(self, serializer):
```

- `serializer` → contains **validated data**
    
- Called **automatically by DRF during object creation**
    

> [!INFO]  
> At this point, **serializer data is already validated**.

---

#### 2️⃣ Saving the Object

```python
serializer.save(user=self.request.user)
```

This does two things:

1. Creates a **Recipe instance**
    
2. Assigns the **authenticated user**
    

Equivalent to:

```python
Recipe.objects.create(
    title=...,
    time_minutes=...,
    price=...,
    user=request.user
)
```

But handled cleanly through the **serializer**.

---

## ⚠️ Why This Fix Was Necessary

Earlier, the test produced a **database integrity error**.

Example problem:

```
IntegrityError: NOT NULL constraint failed: recipe_recipe.user_id
```

Reason:

```
Recipe.user cannot be NULL
```

But the API was saving:

```
Recipe(title="Sample recipe", ...)
```

Instead of:

```
Recipe(title="Sample recipe", user=request.user)
```

After overriding `perform_create()`, the object is saved correctly.

## ⚡ Pro Tips & Shortcuts

### 🚀 1. `perform_create()` is the Correct Hook

In DRF ViewSets:

|Method|Purpose|
|---|---|
|`create()`|Handles the request/response|
|`perform_create()`|Handles database saving|

Always customize **`perform_create()`**, not `create()`.

---

### 🚀 2. Avoid Trusting Client-Side User Fields

Never allow clients to send:

```json
{
  "user": 5
}
```

Instead, enforce:

```
user = request.user
```

This prevents **security issues and data manipulation**.

---

### 🚀 3. DRF Already Does Most of the Work

When using `ModelViewSet`, DRF automatically provides:

- create
    
- retrieve
    
- update
    
- delete
    
- list
    

You only customize **specific behaviors**.
