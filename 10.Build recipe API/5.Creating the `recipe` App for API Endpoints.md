# 📦 Creating the `recipe` App for API Endpoints

## 🎯 Core Concept

After implementing the **Recipe model inside the `core` app**, we now create a **separate Django app called `recipe`**.

This app will contain **all API-related logic**, such as:

- API views / viewsets
- serializers
- endpoint tests
- URL routing

> [!INFO]
> The **core app** stores **database models**, while the **recipe app** stores **API logic**.

This separation keeps the project **modular and scalable**.

---

# 🏗️ Logic Flow

The architecture now looks like this:

```

Client Request  
↓  
Recipe API Endpoint  
↓  
View / ViewSet (recipe app)  
↓  
Serializer  
↓  
Recipe Model (core app)  
↓  
Database

```

Project separation:

```

core app  
↓  
Models + Business Logic

recipe app  
↓  
API Endpoints + Serializers + Tests

````

---

# 💻 Implementation

## 1️⃣ Create the Recipe App

Run the following command inside the Docker container:

```bash
docker compose run --rm app sh -c "python manage.py startapp recipe"
````

This command creates a new Django app called **recipe**.

> [!CODE]  
> `startapp` automatically generates the base Django app structure.

---

# 📂 Generated Folder Structure

After running the command, Django generates:

```
recipe/
 ├── admin.py
 ├── apps.py
 ├── migrations/
 ├── models.py
 ├── tests.py
 ├── views.py
 └── __init__.py
```

However, in this project we **do not need everything**.

---

# 🧹 Cleaning the App

Because our **models are stored in the `core` app**, we remove unnecessary files.

### Remove Unused Files

Delete:

```
recipe/models.py
recipe/admin.py
recipe/migrations/
recipe/tests.py
```

The reason:

```
core app → models
recipe app → API logic
```

> [!TIP]  
> Separating **models and API logic** makes large projects easier to maintain.

---

# 📂 Create a Tests Folder

Instead of using a single `tests.py`, we organize tests into folders.

Create:

```
recipe/tests/
```

Inside it create:

```
test_recipe_api.py
```

Final structure:

```
recipe/
 ├── tests/
 │    └── test_recipe_api.py
 ├── views.py
 ├── apps.py
 └── __init__.py
```

> [!INFO]  
> This structure makes it easier to add **multiple test modules** as the API grows.

Example future structure:

```
tests/
 ├── test_recipe_api.py
 ├── test_tags_api.py
 └── test_ingredients_api.py
```

---

# ⚙️ Enable the App in Django

Next, register the app in Django settings.

Open:

```
app/settings.py
```

Find `INSTALLED_APPS` and add:

```python
INSTALLED_APPS = [
    ...
    "recipe",
]
```

This tells Django:

```
Load the recipe app when the project starts
```

> [!CAUTION]  
> If you forget to add the app to `INSTALLED_APPS`, Django will **not detect the app**.

---

# 🔍 Final Project Architecture

After these steps, the architecture becomes:

```
project/
 ├── app/
 │    └── settings.py
 │
 ├── core/
 │    ├── models.py
 │    └── tests/
 │
 └── recipe/
      ├── tests/
      │    └── test_recipe_api.py
      ├── views.py
      └── apps.py
```

Responsibilities:

|App|Responsibility|
|---|---|
|core|database models|
|recipe|API endpoints|

# ⚡ Pro-Tips & Shortcuts

> [!TIP]  
> Large Django projects often separate **apps by responsibility**, such as:

```
users/
recipes/
orders/
payments/
notifications/
```

---

> [!TIP]  
> Organizing tests into a **tests folder** instead of a single file improves scalability.

Example:

```
tests/
 ├── test_models.py
 ├── test_views.py
 └── test_serializers.py
```

---

> [!CAUTION]  
> Django will **only load apps listed in `INSTALLED_APPS`**.

Always verify after creating a new app.
