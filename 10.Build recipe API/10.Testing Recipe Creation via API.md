# 🧪 Testing Recipe Creation via API (Django REST Framework)

---

## 🎯 Core Concept

When building APIs, **testing object creation through the API layer** is critical.  
Instead of creating objects directly through the model in tests, we simulate a **real client request**.

This ensures the following components work together correctly:

- **API Endpoint**
- **Serializer**
- **View Logic**
- **Database Model**

The goal of this test is to verify that:

1. A **POST request** creates a recipe.
2. The API returns **HTTP 201 (Created)**.
3. The **recipe is correctly stored in the database**.
4. The **authenticated user is assigned to the recipe**.

> [!INFO]
> This test validates the **entire API stack**, not just the model.

---

## 🏗️ Logic Flow (Request Lifecycle)

The test simulates the real **API data flow**:

```

Client Test Request  
│  
▼  
POST /api/recipe/recipes/  
│  
▼  
Django REST ViewSet  
│  
▼  
Serializer Validation  
│  
▼  
Model Instance Created  
│  
▼  
Database Save  
│  
▼  
Response → HTTP 201 Created

````

In the test, we verify both:

- **HTTP response**
- **Database state**

## 💻 Implementation

### 🧪 Test: Creating a Recipe via API

```python
def test_create_recipe(self):
    """Test creating a recipe through the API"""

    payload = {
        'title': 'Sample recipe',
        'time_minutes': 30,
        'price': Decimal('5.99')
    }

    res = self.client.post(RECIPES_URL, payload)

    # Check API response status
    self.assertEqual(res.status_code, status.HTTP_201_CREATED)

    # Retrieve the created recipe from the database
    recipe = Recipe.objects.get(id=res.data['id'])

    # Verify fields match payload
    for k, v in payload.items():
        self.assertEqual(getattr(recipe, k), v)

    # Verify recipe belongs to authenticated user
    self.assertEqual(recipe.user, self.user)
````

---

### 🔍 Key Parts Explained

#### 1️⃣ Creating the Payload

```python
payload = {
    'title': 'Sample recipe',
    'time_minutes': 30,
    'price': Decimal('5.99')
}
```

This dictionary simulates **JSON data sent by a client**.

Example API request:

```json
POST /api/recipe/recipes/

{
  "title": "Sample recipe",
  "time_minutes": 30,
  "price": "5.99"
}
```

---

#### 2️⃣ Sending the API Request

```python
res = self.client.post(RECIPES_URL, payload)
```

This simulates an **HTTP POST request** to the API endpoint:

```
/api/recipe/recipes/
```

---

#### 3️⃣ Validating the Response

```python
self.assertEqual(res.status_code, status.HTTP_201_CREATED)
```

**HTTP 201 Created** is the correct status when a resource is successfully created.

> [!INFO]  
> REST standard:
> 
> - `200 OK` → fetch/update
>     
> - `201 Created` → new resource created
>     
> - `204 No Content` → delete success
>     

---

#### 4️⃣ Fetching the Created Object

```python
recipe = Recipe.objects.get(id=res.data['id'])
```

After the POST request:

- The API returns the **new object ID**
    
- The test retrieves the object from the **database**
    

---

#### 5️⃣ Verifying Fields Dynamically

```python
for k, v in payload.items():
    self.assertEqual(getattr(recipe, k), v)
```

Instead of writing multiple assertions:

```python
self.assertEqual(recipe.title, payload['title'])
self.assertEqual(recipe.time_minutes, payload['time_minutes'])
```

We loop through the payload.

---

### ⚙️ Python `getattr()` Explained

```python
getattr(recipe, k)
```

If:

```
k = "title"
```

This becomes equivalent to:

```
recipe.title
```

But it works **dynamically using variable names**.

> [!INFO]  
> `getattr(object, attribute_name)`  
> retrieves an attribute using a **string variable**

---

#### ❌ Why Not Use Dot Notation?

This **won't work**:

```python
recipe.k
```

Because Python will look for an attribute literally named `"k"`.

Instead, we use:

```python
getattr(recipe, k)
```

---

#### 6️⃣ Verifying User Ownership

```python
self.assertEqual(recipe.user, self.user)
```

This ensures:

- The recipe belongs to the **authenticated user**
    
- The API correctly assigns ownership.

## ⚠️ Expected Test Failure

When running the test initially, you may see an error like:

```
IntegrityError
```

This happens because:

- The **Recipe model requires a user**
    
- But the **ViewSet does not yet assign the authenticated user**
    

So the database rejects the insert.

> [!CAUTION]  
> Django REST Framework already handles **90% of object creation logic**.  
> The missing piece is assigning:
> 
> ```python
> recipe.user = request.user
> ```

We will fix this in the **ViewSet** in the next step.

## ⚡ Pro Tips & Shortcuts

### 🚀 1. Always Test Through the API

Avoid this in API tests:

```python
Recipe.objects.create(...)
```

Instead test with:

```
POST request → API
```

This validates:

- serializers
    
- permissions
    
- view logic
    
- authentication
    
- database interaction
    

---

### 🚀 2. Use Loops to Reduce Test Boilerplate

Instead of writing many assertions:

```python
self.assertEqual(recipe.title, payload['title'])
self.assertEqual(recipe.price, payload['price'])
```

Use:

```python
for k, v in payload.items():
```

Cleaner and scalable.

---

### 🚀 3. Always Validate Ownership

In multi-user systems:

```
User A should NOT see User B's data
```

Testing ownership prevents **data leakage bugs**.
