# 🧪 Creating the Recipe Model Test (TDD Approach)

## 🎯 Core Concept

Before implementing the **Recipe model**, we first write a **test** to define the expected behavior.

This follows **Test Driven Development (TDD)**:

1️⃣ Write a failing test  
2️⃣ Implement the feature  
3️⃣ Make the test pass  

> [!INFO]
> The idea of **TDD** is to define *what the code should do* before actually writing the implementation.

---

# 🏗️ Logic Flow

For this step, the data flow is focused on **database model testing**.

```

Test Case  
↓  
Create User  
↓  
Create Recipe Object  
↓  
Store in Database  
↓  
Validate Object Fields  
↓  
Verify String Representation

```

Key idea:

- A **Recipe belongs to a User**
- The test ensures the model behaves correctly before implementation.

---

# 💻 Implementation

### 📂 Test Location

The test is added inside the **core app**, since that app contains our models.

```

core/  
├── models.py  
├── tests/  
│ └── test_models.py

````

---

## 1️⃣ Import Dependencies

```python
from decimal import Decimal
from django.test import TestCase
from django.contrib.auth import get_user_model

from core import models
````

> [!INFO]  
> `Decimal` is used instead of float to **avoid floating point precision issues**.

---

## 2️⃣ Create the Test Case

```python
class ModelTests(TestCase):

    def test_create_recipe(self):
        """Test creating a recipe is successful"""

        user = get_user_model().objects.create_user(
            email="test@example.com",
            password="testpass123"
        )

        recipe = models.Recipe.objects.create(
            user=user,
            title="Sample recipe name",
            time_minutes=5,
            price=Decimal("5.50"),
            description="Sample recipe description"
        )

        self.assertEqual(str(recipe), recipe.title)
```

# ⚠️ Decimal vs Float for Money

There are **two ways to store decimal values**:

|Type|Description|
|---|---|
|`float`|Standard floating-point number|
|`Decimal`|More precise numeric representation|

Example:

```python
Decimal("5.50")
```

> [!INFO]  
> `Decimal` is more **accurate for numeric values** than floats.

---

### 💡 Real Financial Systems

In **production financial systems**, best practice is usually:

```
Store currency as INTEGER
```

Example:

```
550 cents instead of 5.50 dollars
```

Why?

- avoids rounding errors
    
- avoids floating-point precision issues
    
- easier calculations
    

Example:

```
Price = 550  # cents
```

> [!CAUTION]  
> For this project, using **Decimal is acceptable** because the price is only informational.

# 🔎 String Representation Test

This line verifies the **string representation of the model**.

```python
self.assertEqual(str(recipe), recipe.title)
```

Meaning:

```
str(recipe) → "Sample recipe name"
```

This requires implementing:

```python
def __str__(self):
    return self.title
```

inside the **Recipe model**.

# ⚡ Pro-Tips & Shortcuts

> [!TIP]  
> Always write **tests before models** when practicing TDD.

---

> [!TIP]  
> Use `Decimal("5.50")` instead of `5.50`.

Reason:

```
Decimal("5.50")  ✅ precise
5.50 (float)     ❌ rounding issues
```

---

> [!CAUTION]  
> Always link models to the authenticated user when building **multi-user APIs**.

Example:

```python
user = models.ForeignKey(User)
```

Without this, users could **access each other's data**.
