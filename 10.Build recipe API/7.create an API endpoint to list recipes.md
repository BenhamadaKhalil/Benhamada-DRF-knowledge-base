# 1. What is the goal of this lesson?

The goal was to create an **API endpoint to list recipes**.

Meaning the frontend (React, mobile app, etc.) can request:

```
GET /api/recipe/recipes/
```

and receive JSON like:

```json
[
  {
    "id": 1,
    "title": "Pizza",
    "time_minutes": 30,
    "price": "12.00",
    "link": "http://example.com"
  }
]
```

To achieve this, Django REST Framework needs **3 main components**:

```
Database Model
      ↓
Serializer
      ↓
ViewSet
      ↓
URL Router
      ↓
API Endpoint
```

---

# 2. Step 1 — Serializer (convert model → JSON)

File created:

```
recipe/serializers.py
```

Code concept:

```python
class RecipeSerializer(serializers.ModelSerializer):

    class Meta:
        model = Recipe
        fields = ['id', 'title', 'time_minutes', 'price', 'link']
        read_only_fields = ['id']
```

### Why we need this

Django models are **Python objects**.

Example:

```python
Recipe(title="Pizza", time_minutes=30)
```

But APIs must return **JSON**.

Serializer does the conversion:

```
Python Object
     ↓
Serializer
     ↓
JSON
```

Example output:

```json
{
 "id": 1,
 "title": "Pizza",
 "time_minutes": 30,
 "price": "12.00"
}
```

# 3. Step 2 — ViewSet (the API logic)

File:

```
recipe/views.py
```

Main class:

```python
class RecipeViewSet(viewsets.ModelViewSet):
```

### What is a ViewSet?

It is a **controller for the API**.

It handles actions like:

|HTTP Method|Action|
|---|---|
|GET|list recipes|
|GET /id|retrieve one|
|POST|create recipe|
|PUT/PATCH|update|
|DELETE|delete|

So **one class handles the full CRUD API.**

---

### Inside the viewset

#### Serializer

```python
serializer_class = serializers.RecipeSerializer
```

This tells the API **how to convert data to JSON.**

---

#### Queryset

```python
queryset = Recipe.objects.all()
```

This tells the API **where the data comes from (database).**

---

#### Authentication

```python
authentication_classes = [TokenAuthentication]
permission_classes = [IsAuthenticated]
```

Meaning:

```
User must send token
      ↓
User must be logged in
      ↓
Otherwise API returns 401
```

---

# 4. Step 3 — Filter recipes by user

Important override:

```python
def get_queryset(self):
    return self.queryset.filter(
        user=self.request.user
    ).order_by('-id')
```

Why?

Without this:

```
User A could see User B recipes
```

With this:

```
User A only sees:
Recipe(user=A)
```

So each user sees **their own recipes only**.

---

# 5. Step 4 — Router (automatic API URLs)

File created:

```
recipe/urls.py
```

Key code:

```python
router = DefaultRouter()

router.register('recipes', views.RecipeViewSet)
```

The router **automatically generates endpoints**.

So instead of writing many URLs manually, Django REST creates them.

Generated endpoints:

|Endpoint|Action|
|---|---|
|GET /recipes|list|
|POST /recipes|create|
|GET /recipes/{id}|retrieve|
|PATCH /recipes/{id}|update|
|DELETE /recipes/{id}|delete|

---

# 6. Step 5 — Include URLs in main project

Inside:

```
app/urls.py
```

They added:

```python
path('api/recipe/', include('recipe.urls'))
```

So the final API becomes:

```
/api/recipe/recipes/
```
