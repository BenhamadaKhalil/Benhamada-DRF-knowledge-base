## 🎯 Core Concept

### ✅ Why?

A backend app needs a reliable **User API** so clients (web/mobile/desktop) can:

- **Register** users
    
- **Authenticate** users securely
    
- **Let users manage their own profile**
    
- Provide a clean interface for future features (recipes, permissions, roles, etc.)
    

### ✅ What?

In this section, we built a complete **User API module** with DRF, including endpoints for:

- Creating users
    
- Token-based login
    
- Managing the authenticated user profile
    
- Manual verification through Swagger/OpenAPI docs
    

> [!INFO]  
> This is the foundation for any authenticated DRF project: registration + login + “me” profile management.

---

## 🏗️ Logic Flow (Overall API Data Flow)

```text
Client
  ↓
POST /user/create/        → UserSerializer.create() → DB (new user)
  ↓
POST /user/token/         → AuthTokenSerializer.validate() → Token generated
  ↓
Authorization: Token xxx  → TokenAuthentication → request.user set
  ↓
GET/PATCH /user/me/       → ManageUserView.get_object() → UserSerializer.update()
  ↓
Response (profile data / updated data)
```

## 💻 Implementation Highlights (What You Built)

### 🧱 1) Designed the User API

- Defined what endpoints are needed for user lifecycle:
    
    - register
        
    - authenticate
        
    - manage profile (`/me/`)
        

> [!INFO]  
> Good API design keeps responsibilities separate: creation is not the same as profile updates.

---

### 📦 2) Created a Dedicated `user` App

- You separated user-related code into its own Django app:
    
    - serializers
        
    - views
        
    - urls
        
    - tests
        

✅ Result: cleaner architecture and easier maintenance.

---

### 🧾 3) Implemented Create User Endpoint

- Added an endpoint that allows clients to create new users
    
- Ensured correct response codes and response payload shape via tests
    

> [!CAUTION]  
> User creation must **hash passwords** (never store plain text).

---

### 🔐 4) Added Authentication (Token Auth)

- Enabled `rest_framework.authtoken` in settings
    
- Created an API to obtain tokens (login)
    
- Covered multiple authentication options in DRF (conceptually), then implemented token auth
    

> [!INFO]  
> Token Auth is simple and works well for learning + many APIs, especially when you control the clients.

---

### 👤 5) Added “Manage Profile” API (`/me/`)

- Built an endpoint for authenticated users to:
    
    - retrieve their profile (GET)
        
    - update their profile (PATCH/PUT)
        
- Required authentication and restricted methods (POST not allowed)
    

> [!PROTIP]  
> `RetrieveUpdateAPIView + get_object() = request.user` is the standard pattern for `/me/`.

---

### 🌐 6) Tested via Swagger / Browser Docs

- Verified behavior manually:
    
    - unauthorized request returns 401
        
    - create user works (201)
        
    - token retrieval returns a token (200)
        
    - authorize in Swagger with `Token <value>`
        
    - `/me/` returns and updates the authenticated profile
        

> [!CAUTION]  
> Swagger auth header must match exactly: `Token <token>` (capital T + space), or auth fails.

---

## ⚡ Pro-Tips & Gotchas

> [!PROTIP]  
> Keep **tests split** into:

- Public (unauthenticated)
    
- Private (authenticated with `force_authenticate`)
    

> [!CAUTION]  
> Always override serializer `update()` if password can be updated—use `set_password()`.

> [!INFO]  
> Restarting docker after enabling `authtoken` matters because migrations create token tables.
