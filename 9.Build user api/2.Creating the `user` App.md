# 🧩 Creating the `user` App – Project Setup (DRF)

---

## 🎯 Core Concept

Before building the **Users API**, we must create a dedicated Django app to isolate all user-related API logic.

### ✅ Why?

- Separation of concerns 🧠
    
- Clean project structure 🏗️
    
- Scalability for authentication features 🔐
    

Instead of mixing everything inside `core`, we create a **dedicated `user` app**.

---

## 🏗️ Logic Flow

```text
Docker Container
    ↓
Django Management Command
    ↓
New App Created
    ↓
Cleanup Unnecessary Files
    ↓
Register App in settings.py
    ↓
App Enabled in Project
```

---

## 💻 Implementation

### 1️⃣ Create the App (Inside Docker)

Run this from your project root:

```bash
docker compose run --rm app sh -c "python manage.py startapp user"
```

> [!INFO]  
> We run the command inside Docker to ensure the app is created inside the container environment — not your local machine Python.

---

### 2️⃣ New Folder Structure

After running the command, Django creates:

```text
user/
├── admin.py
├── apps.py
├── migrations/
├── models.py
├── tests.py
└── views.py
```

---

## 🧹 Cleanup Phase (Important Architecture Decision)

In this course structure:

- All **models** live in `core`
    
- All **admin logic** lives in `core`
    
- All **migrations** live in `core`
    

So we remove unnecessary files from `user`:

❌ Delete:

- `migrations/`
    
- `admin.py`
    
- `models.py`
    
- `tests.py`
    

---

### 3️⃣ Create a Proper Test Structure

Instead of a single `tests.py`, we create a modular test directory.

📁 Inside `user/`:

```text
user/
├── tests/
│   └── __init__.py
├── apps.py
└── views.py
```

Create:

```bash
mkdir user/tests
touch user/tests/__init__.py
```

> [!INFO]  
> Creating `__init__.py` tells Python this directory is a module.  
> This allows structured test files like:
> 
> - `test_user_api.py`
>     
> - `test_serializers.py`
>     

Much cleaner for scaling 🧼✨

---

## ⚙️ Register the App in Django

Open:

```text
app/app/settings.py
```

Add `'user'` to `INSTALLED_APPS`:

```python
INSTALLED_APPS = [
    ...
    'drf_spectacular',
    'user',
]
```

> [!CAUTION]  
> If you forget this step, Django won’t recognize your app.  
> Models, views, and URLs won’t be registered.

---

## 🧠 Architectural Insight

Notice something important here:

- `core` → business logic & database layer
    
- `user` → API layer for user-related endpoints
    

This is a **clean layered architecture approach**:

- Database models separated from API logic.
    
- Better maintainability long-term.
    

---

## ⚡ Pro-Tips & Gotchas

### 🐳 Always Run Django Commands in Docker

If you're using Docker, never run `manage.py` directly on your machine.

Wrong:

```bash
python manage.py startapp user
```

Correct:

```bash
docker compose run --rm app sh -c "python manage.py startapp user"
```

---

### 🗂️ Why Not Keep Migrations in `user`?

Because this project centralizes:

- Models
    
- Migrations
    
- Admin
    

Inside `core` to maintain a **single source of truth**.

This is a design choice — not a Django rule.

---

### 🧪 Why Use a `tests/` Directory?

When your project grows:

```text
tests/
├── test_create_user.py
├── test_token_api.py
├── test_profile_api.py
```

Much cleaner than a 1000-line `tests.py`.

Senior dev move 👌
