## 🎯 Core Concept

In this section, we design a **Users API** responsible for:

- 📝 **User Registration**
    
- 🔐 **Authentication via Token**
    
- 👤 **Profile Retrieval & Update**
    

This API forms the foundation of the **authentication system** of our project.

> [!INFO]  
> The goal is to implement a **token-based authentication workflow** where:
> 
> 1. A user registers.
>     
> 2. The user requests a token.
>     
> 3. The token is used to authenticate future API requests.
>     

---

## 🏗️ API Endpoints Overview

We will implement **three core endpoints**:

|Endpoint|Method|Purpose|
|---|---|---|
|`/api/user/create/`|`POST`|Register a new user|
|`/api/user/token/`|`POST`|Generate authentication token|
|`/api/user/me/`|`GET`|Retrieve current user profile|
|`/api/user/me/`|`PATCH`|Update current user profile|

---

## 🔁 Logic Flow

### 📝 1️⃣ User Registration

```
Client -> POST /api/user/create/ 
        -> View 
        -> Serializer (validation)
        -> User Model (create)
        -> Response
```

- Client sends: `email + password`
    
- Server validates data
    
- User is created in the database
    
- Password is properly hashed
    

---

### 🔐 2️⃣ Token Authentication

```
Client -> POST /api/user/token/
        -> Authentication Serializer
        -> Validate credentials
        -> Generate Token
        -> Return Token
```

- Client sends: `email + password`
    
- If valid → return token
    
- Token is used in future requests via:
    

```
Authorization: Token <your_token_here>
```

---

### 👤 3️⃣ Profile Management

```
Authenticated Client 
        -> GET /api/user/me/
        -> Return current user data
```

```
Authenticated Client 
        -> PATCH /api/user/me/
        -> Update user instance
```

> [!CAUTION]  
> `/me/` endpoint must be **authentication-protected**.  
> Only the authenticated user can access their own profile.

## 💻 Implementation (High-Level Structure)

### urls.py

```python
from django.urls import path
from user import views

app_name = 'user'

urlpatterns = [
    path('create/', views.CreateUserView.as_view(), name='create'),
    path('token/', views.CreateTokenView.as_view(), name='token'),
    path('me/', views.ManageUserView.as_view(), name='me'),
]
```

---

### 1️⃣ Create User View

```python
from rest_framework import generics
from user.serializers import UserSerializer

class CreateUserView(generics.CreateAPIView):
    """
    Create a new user in the system.
    """
    serializer_class = UserSerializer
```

---

### 2️⃣ Create Token View

```python
from rest_framework.authtoken.views import ObtainAuthToken
from rest_framework.settings import api_settings

class CreateTokenView(ObtainAuthToken):
    """
    Create a new auth token for user.
    """
    renderer_classes = api_settings.DEFAULT_RENDERER_CLASSES
```

> [!INFO]  
> We override `renderer_classes` to enable the browsable API in development.

---

### 3️⃣ Manage User View

```python
from rest_framework import generics, authentication, permissions

class ManageUserView(generics.RetrieveUpdateAPIView):
    """
    Retrieve or update authenticated user.
    """
    serializer_class = UserSerializer
    authentication_classes = [authentication.TokenAuthentication]
    permission_classes = [permissions.IsAuthenticated]

    def get_object(self):
        return self.request.user
```

> [!CODE]  
> `get_object()` ensures the endpoint always returns the **currently authenticated user**, not any arbitrary user ID.

## ⚡ Pro-Tips & Gotchas

### 🔑 Always Hash Passwords

Make sure your serializer calls `create_user()` instead of `create()` to ensure password hashing.

---

### 🔒 Never Expose Password Field

In your serializer:

```python
extra_kwargs = {
    'password': {'write_only': True, 'min_length': 5}
}
```

---

### 🧠 Why `/me/` Instead of `/users/<id>/`?

Because:

- It prevents horizontal privilege escalation.
    
- Users cannot access other users' data.
    
- Cleaner and safer API design.
