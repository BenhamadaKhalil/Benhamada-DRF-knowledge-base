## 🎯 Core Concept

Before implementing `/api/user/token/`, we write **unit tests** to define correct behavior for token creation (login).

### ✅ What these tests guarantee

- Valid credentials → **token returned** + **200 OK**
    
- Invalid credentials → **no token** + **400 Bad Request**
    
- Blank password → **no token** + **400 Bad Request**
    
- URL mapping must exist → `reverse('user:token')` should resolve
    

> [!INFO]  
> Token endpoint is part of _public_ API because users need to log in _before_ they can access private endpoints.

---

## 🏗️ Logic Flow

```text
Test -> create a user in DB
     -> POST /api/user/token/ with credentials
     -> Assert:
          - token exists (success case)
          - no token (error cases)
          - proper HTTP status codes
```

## 🧱 Setup Changes in `test_user_api.py`

### 1) Add Token URL Constant

At the top of `user/tests/test_user_api.py` (near `CREATE_USER_URL`):

> [!CODE]

```python
TOKEN_URL = reverse('user:token')
```

✅ This matches the design: URL name `token` inside the `user` namespace.

> [!CAUTION]  
> If your URL config isn’t wired yet, `reverse('user:token')` will fail with **NoReverseMatch** — this is expected until the API is implemented.

## ✅ Test 1: Create Token for Valid Credentials

This test proves successful login returns a token.

> [!CODE]

```python
def test_create_token_for_user(self):
    """Test generates token for valid credentials."""
    user_details = {
        'name': 'Test Name',
        'email': 'test@example.com',
        'password': 'test-user-password123',
    }
    create_user(**user_details)

    payload = {
        'email': user_details['email'],
        'password': user_details['password'],
    }

    res = self.client.post(TOKEN_URL, payload)

    self.assertIn('token', res.data)
    self.assertEqual(res.status_code, status.HTTP_200_OK)
```

🧠 Key idea:

- We create a real user in DB first
    
- Then login using the same credentials
    
- Expect a `token` in response

## ❌ Test 2: Invalid Credentials → 400 + No Token

If password is wrong, token must not be generated.

> [!CODE]

```python
def test_create_token_bad_credentials(self):
    """Test returns error if credentials invalid."""
    create_user(email='test@example.com', password='goodpass123')

    payload = {'email': 'test@example.com', 'password': 'badpass123'}
    res = self.client.post(TOKEN_URL, payload)

    self.assertNotIn('token', res.data)
    self.assertEqual(res.status_code, status.HTTP_400_BAD_REQUEST)
```

## 🚫 Test 3: Blank Password → 400 + No Token

This ensures serializer validation blocks empty password.

> [!CODE]

```python
def test_create_token_blank_password(self):
    """Test posting blank password returns an error."""
    payload = {'email': 'test@example.com', 'password': ''}
    res = self.client.post(TOKEN_URL, payload)

    self.assertNotIn('token', res.data)
    self.assertEqual(res.status_code, status.HTTP_400_BAD_REQUEST)
```

## 🧯 Debugging Note: “Invalid Syntax” Failure

During test writing, a failure occurred due to a typo (e.g., missing quotes / malformed email string like `test example dot com`).

```python
'email': 'test@example.com'
```

## ⚡ Pro-Tips & Gotchas

- 🧭 Use `reverse('user:token')` so URL changes don’t break tests.
    
- 🔐 Check for **absence of token** in error cases (`assertNotIn`).
    
- 🧪 Separate “bad password” vs “blank password”:
    
    - bad password → authentication fails
        
    - blank password → validation fails
        
- 🧱 Token endpoint is **public**, so it should not require auth.
