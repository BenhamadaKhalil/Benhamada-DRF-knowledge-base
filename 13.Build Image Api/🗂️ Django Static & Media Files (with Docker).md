## What Are Static & Media Files?

These are files **not generated by Python code**, such as:

- Images
    
- CSS
    
- JavaScript
    
- Icons
    

They are required for styling and user-uploaded content.

---

## Types of Files

### 📁 Media Files

- **Uploaded by users at runtime**
    
- Not part of the source code
    
- Examples:
    
    - Profile pictures
        
    - Recipe images
        

### 📁 Static Files

- **Generated at build time or app startup**
    
- Shipped with the source code or dependencies
    
- Examples:
    
    - Django Admin CSS/JS
        
    - DRF Browsable API assets
        
    - App styling files
        

> Even though this project is a REST API, static files are still used indirectly by Django Admin and DRF.

---

## Django Settings Configuration

Add these to `settings.py`:

### URLs (browser access)

```python
STATIC_URL = '/static/static/'
MEDIA_URL = '/static/media/'
```

### File system paths (server storage)

```python
STATIC_ROOT = '/vol/web/static'
MEDIA_ROOT = '/vol/web/media'
```

- **URLs** → how files are accessed via browser
    
- **ROOT paths** → where files are stored on disk
    

---

## Docker Volumes & File Persistence

Docker volumes are used to:

- Persist data between container restarts
    
- Share files between services
    

### Volume setup

```text
/vol/web/
├── static/
└── media/
```

This volume stores:

- All static files
    
- All uploaded media files
    

---

## Development vs Production

### 🧪 Development Mode

- Uses Django development server
    
- Automatically serves static files
    
- Example:
    
    ```
    /static/static/admin/css/base.css
    ```
    
- Django finds static files inside installed apps automatically
    

Media files:

- Loaded directly from `MEDIA_ROOT`
    
- Uploaded during runtime
    

---

### 🚀 Production Mode

- Django **does NOT** serve static files
    
- Use a **reverse proxy (e.g., Nginx)**
    

How it works:

- Proxy maps `/static/` to `/vol/web/`
    
- Files served directly from filesystem
    

Examples:

- `/static/media/image.jpg` → `/vol/web/media/image.jpg`
    
- `/static/static/admin/css/base.css` → `/vol/web/static/admin/css/base.css`
    

---

## `collectstatic` Command

Used for production setup.

### Command:

```bash
python manage.py collectstatic
```

### What it does:

- Gathers all static files from:
    
    - Django
        
    - Third-party apps
        
- Copies them into `STATIC_ROOT`
    

### Why it matters:

- Required for serving static files in production
    
- Reverse proxy needs all static files in one place
    

---

## Key Takeaways

- **Media** = user uploads (runtime)
    
- **Static** = app assets (build time)
    
- Django dev server handles static automatically
    
- Production requires:
    
    - `collectstatic`
        
    - Reverse proxy (Nginx)
        
    - Docker volumes for persistence
