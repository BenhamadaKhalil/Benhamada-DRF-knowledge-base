# ⚙️ Create `docker-compose.yml` — Obsidian Notes

> 🎯 Goal: Create a Docker Compose config to run the Django app container easily (with ports, volumes, and a default command).

---

# 📄 1) Create the file

In the **root** of your project, create:

```
docker-compose.yml
```

> [!tip] YAML indentation  
> Use **spaces (not tabs)**. Many devs prefer **2 spaces** for readability.

---

# ✅ 2) Add the Docker Compose configuration (copy-paste)

```yaml
version: "3.9"

services:
  app:
    build:
      context: .
    ports:
      - "8000:8000"
    volumes:
      - ./app:/app
    command: >
      sh -c "python manage.py runserver 0.0.0.0:8000"
```

---

# 🧠 3) What each part means (simple)

## 🏷️ `version: "3.9"`

Specifies the Docker Compose **syntax version** used by this file.

> [!note] Why it matters  
> Keeps your config stable if Docker Compose introduces new syntax versions later.

---

## 🧩 `services:`

Main block that lists all containers (services) your project needs.

In this course, we start with one service:

- ✅ `app` → your Django application container
    

---

## 🏗️ `build: context: .`

Tells Docker Compose:

- Build the image using the `Dockerfile` located in the **current folder** (`.`)
    

> [!tip] Mental model  
> `context: .` = “use this folder as the build source”

---

## 🌐 `ports: "8000:8000"`

Maps ports like this:

```
Your PC (8000)  →  Container (8000)
```

So you can open Django in your browser at:

```
http://127.0.0.1:8000
```

---

## 📁 `volumes: ./app:/app`

Links your local code to the container:

```
Local ./app folder  →  Container /app folder
```

✅ This enables **live syncing**:

- When you edit code locally → container sees changes immediately
    
- No need to rebuild the image every change
    

---

## ▶️ `command: ... runserver 0.0.0.0:8000`

This is the **default command** that runs when the service starts.

### Why `0.0.0.0`?

It makes Django listen on all interfaces inside the container so your host machine can access it.

> [!important] If you use `127.0.0.1` inside Docker  
> Django would only be accessible from inside the container, not from your PC.

---

# 🛠️ 4) Build using Docker Compose

Run:

```bash
docker compose build
```

> [!note] Equivalent  
> Similar to `docker build .`, but it builds using the Compose service configuration and tags correctly.

---

# ✅ Quick Checklist

- ✅ `docker-compose.yml` exists in project root
    
- ✅ Indentation uses spaces
    
- ✅ Port mapping `8000:8000` added
    
- ✅ Volume mapping `./app:/app` added
    
- ✅ Default command runs Django server
    
- ✅ `docker compose build` works
