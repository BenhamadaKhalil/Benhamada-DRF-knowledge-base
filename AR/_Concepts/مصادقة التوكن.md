# 🪙 مصادقة التوكن — Token Authentication

> 🇬🇧 النسخة الإنجليزية: [[EN/_Concepts/Token Authentication|Token Authentication]]

---

## 🎯 الفكرة الأساسية

**بيانات الاعتماد مرة واحدة، ثم التوكن مرات كثيرة.**

يُرسل العميل البريد وكلمة المرور إلى `/api/user/token/` مرة واحدة، فيحصل على مفتاح مبهم، ثم يُرفق هذا المفتاح مع كل طلب لاحق:

```http
Authorization: Token 9c1f2e4a8b...
```

> [!WARNING] الكلمة هي `Token` وليست `Bearer`
> `Bearer` هي صيغة JWT. معظم عملاء HTTP تستخدمها افتراضيًا، ورسالة الخطأ في DRF لا تذكر الكلمة إطلاقًا. هذا **أكثر خطأ شيوعًا في DRF على الإطلاق**.

---

## ⚙️ الإعداد

```python
# app/app/settings.py
INSTALLED_APPS = [..., "rest_framework.authtoken"]

REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": [
        "rest_framework.authentication.TokenAuthentication",
    ],
}
```

يبحث DRF عن المفتاح في جدول `authtoken_token` ثم يضبط `request.user`. قراءة واحدة بمفتاح أساسي مُفهرَس لكل طلب.

## ⚖️ المقايضة

| المكسب | الثمن |
| --- | --- |
| **الإبطال الفوري** — احذف الصف فيخرج العميل | قراءة من قاعدة البيانات مع كل طلب |
| لا حاجة إلى حزمة خارجية | التوكن الافتراضي **لا ينتهي أبدًا** |
| يعمل من المتصفّح والهاتف و`curl` بالطريقة نفسها | — |

هذه المقايضة معكوسة تمامًا في [[EN/_Concepts/JWT|JWT]] 🇬🇧: لا قراءة من قاعدة البيانات، ولا إبطال.

## ⏳ إصلاح مشكلة عدم الانتهاء

التوكن الافتراضي صالح إلى الأبد — أي أن توكنًا سُرق عام ٢٠٢٤ يعمل عام ٢٠٢٧. الحل صنف مصادقة مخصّص:

```python
# app/core/authentication.py
from datetime import timedelta

from django.utils import timezone
from rest_framework.authentication import TokenAuthentication
from rest_framework.exceptions import AuthenticationFailed


class ExpiringTokenAuthentication(TokenAuthentication):
    """مصادقة توكن تنتهي صلاحيته بعد ٧ أيام."""

    def authenticate_credentials(self, key):
        user, token = super().authenticate_credentials(key)

        if token.created < timezone.now() - timedelta(days=7):
            token.delete()
            raise AuthenticationFailed("Token has expired.")

        return user, token
```

هذا الصنف وحده يُلغي الحجّة الأساسية ضدّ توكنات DRF.

## 🔒 أين تُخزَّن؟

| العميل | خزّنه في | لا تخزّنه أبدًا في |
| --- | --- | --- |
| iOS | Keychain | `UserDefaults` |
| Android | EncryptedSharedPreferences | `SharedPreferences` |
| تطبيق ويب | كوكي `httpOnly` `Secure` | `localStorage` |
| سطر الأوامر | متغيّر بيئة | ملف إعدادات مرفوع إلى git |

> [!CAUTION] `localStorage` هو الخطأ المتكرّر
> مريح، وكل الدروس تستخدمه، وأي سكربت JavaScript على الصفحة يستطيع قراءته — بما في ذلك أي شيء يُحقَن عبر ثغرة XSS أو عبر حزمة npm مُخترَقة.

---

## 🚪 لماذا لا يوجد endpoint لتسجيل الخروج؟

تسجيل الخروج في نظام التوكن هو **حذف التوكن من جهة العميل**. يمكنك إنشاء endpoint يحذف الصف من قاعدة البيانات، لكنه غير موثوق كإشارة: قد يحذف المستخدم التطبيق وهو مسجّل الدخول، أو ينقطع اتصاله، أو يمسح المتصفّح تخزينه فجأة.

---

## ⚠️ أخطاء شائعة

- **`401` مع توكن تعرف أنه صحيح** ← كتبت `Bearer` بدل `Token`.
- **كل الطلبات `401` حتى التسجيل** ← `IsAuthenticated` مضبوطة عالميًا ولم تُستثنَ نقطة التسجيل.
- **`403 CSRF Failed`** ← أنت على مسار `SessionAuthentication`، لا على مصادقة التوكن.
- **توكن صالح لكن القائمة فارغة** ← هذا **صحيح**: `get_queryset()` يُرشِّح حسب المالك. راجع [[الصلاحيات]].
