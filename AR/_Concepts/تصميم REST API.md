# 🏛️ تصميم REST API

> 🇬🇧 النسخة الإنجليزية: [[EN/_Concepts/REST API Design|REST API Design]]

---

## 🎯 القاعدة الأولى

REST يعني: **موارد يُعرّفها المسار، وأفعال يُعبّر عنها الـ HTTP method.**
المسار يقول **ماذا**، والطريقة تقول **ماذا تفعل به**.

```text
✅ GET    /recipes/          اعرض القائمة
✅ POST   /recipes/          أنشئ
✅ GET    /recipes/5/        اقرأ واحدًا
✅ PATCH  /recipes/5/        عدّل
✅ DELETE /recipes/5/        احذف

❌ GET  /getRecipes/
❌ POST /createRecipe/
❌ POST /recipes/5/delete/
```

**إن احتوى مسارك على فعل، فالطريقة لا تؤدّي وظيفتها.**

---

## 📐 المبادئ

| المبدأ | في الممارسة |
| --- | --- |
| أسماء، بصيغة الجمع | `/recipes/` لا `/recipe/` |
| التداخل يُعبّر عن الملكيّة | `/recipes/5/upload-image/` |
| الأفعال تحملها الطرق | GET يقرأ، POST يُنشئ، PATCH يُعدّل، DELETE يحذف |
| رموز الحالة تحمل النتيجة | `201` عند الإنشاء، `204` عند الحذف، `400` عند خطأ الإدخال |
| الطرق الآمنة لا تُغيّر شيئًا | `GET`، `HEAD`، `OPTIONS` |
| الطرق مُتكافئة التكرار | `PUT` و`DELETE` مرّتين = مرة واحدة |
| عديم الحالة | كل طلب يحمل بيانات اعتماده |

## 💡 صمّم حول مهمّة المستخدم، لا حول جداولك

أوضح مثال في هذا المشروع: **لا توجد `POST /tags/`.**

```json
POST /recipes/  {"title": "كاري", "tags": [{"name": "تايلندي"}]}
```

تخيّل البديل. لو احتاجت الوسوم نقطة إنشاء خاصّة، لاضطُرّ العميل إلى:

```text
١. POST /tags/  {"name": "تايلندي"}   ← لكن هل هو موجود؟ 409؟ ابحث أولًا؟
٢. GET  /tags/?name=تايلندي            ← سباق تزامن إن وصل طلبان معًا
٣. POST /recipes/  {"tags": [7]}
```

ثلاث رحلات، وسباق تزامن، وإجبار العميل على إدارة هويّة وسوم لم يسأل عنها أصلًا.

**المستخدم يكتب وصفة. هو لا يُدير تصنيفًا للوسوم.**

> [!TIP] عدم إتاحة عملية قرارٌ تصميمي
> نقطة نهاية غير موجودة لا يمكن إساءة استخدامها، ولا تُنشئ تكرارًا، ولا تحتاج اختبارات.

---

## 🚪 حين لا يناسب REST

بعض العمليات ليست CRUD بطبيعتها: `/api/user/token/`، `/export/`، مُستقبِل webhook.

صمّمها كـ [[APIView وأصناف العروض|APIView]] وتوقّف عن القلق بشأن «النقاء». مسارٌ مُقحَم في قالب REST لعملية هي RPC في جوهرها أسوأ من مسار صادق.

## 🔢 رموز الحالة الأساسية

| الرمز | متى |
| --- | --- |
| `200` | نجح `GET` / `PUT` / `PATCH` وهناك محتوى |
| `201` | أنشأ `POST` موردًا |
| `204` | نجح `DELETE` — **بلا محتوى إطلاقًا** |
| `400` | فشل التحقّق |
| `401` | **لا نعرف من أنت** |
| `403` | نعرفك، والجواب لا |
| `404` | غير موجود — أو ليس لك |
| `429` | تجاوزت الحدّ |

**`401` مقابل `403`:** الأولى تعني «حاول مجدّدًا ببيانات اعتماد»، والثانية تعني «لا فائدة من المحاولة».

راجع [[الصلاحيات]] لسبب تفضيل `404` على `403` لكائن يخصّ غيرك.
