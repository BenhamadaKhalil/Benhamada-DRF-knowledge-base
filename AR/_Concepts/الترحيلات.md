# 🔄 الترحيلات — Migrations

> 🇬🇧 النسخة الإنجليزية: [[EN/_Concepts/Django Migrations|Django Migrations]]

---

## 🎯 الفكرة

**نظام تحكّم بالإصدارات لمخطّط قاعدة بياناتك.** كل ترحيل ملف بايثون يصف تغييرًا واحدًا، ويُسجّل Django ما طُبِّق منها في جدول `django_migrations`.

```bash
docker compose run --rm app sh -c "python manage.py makemigrations"
```

```bash
docker compose run --rm app sh -c "python manage.py migrate"
```

| الأمر | الوظيفة |
| --- | --- |
| `makemigrations` | يُقارن نماذجك بآخر ترحيل ← يكتب ملفًا جديدًا |
| `migrate` | يُطبّق غير المُطبَّق على قاعدة البيانات |
| `showmigrations` | ما الذي طُبِّق؟ |
| `sqlmigrate core 0002` | الـ SQL الذي سيُنفَّذ فعلًا |
| `migrate core 0001` | **التراجع** إلى تلك النقطة |

> [!WARNING] الترحيلات كود — ارفعها إلى git
> تعديل في `models.py` بلا ترحيله يعني أن قاعدة بيانات كل زميل تنحرف عن قاعدتك بصمت، وأن الـ CI يفشل على جهاز ليس جهازك.

---

## 🧯 المواقف التي ستواجهها

| الموقف | الحلّ |
| --- | --- |
| «حقل غير قابل للإفراغ بلا قيمة افتراضية» | أضِف `null=True` أو `default=...` |
| تحتاج تعبئة بيانات | `makemigrations --empty` ثم عملية `RunPython` |
| ترحيل خاطئ لم تُرسله بعد | `migrate core 0001`، احذف الملف، أعِد التوليد |
| ترحيل خاطئ **أُرسِل** | **اكتب ترحيلًا جديدًا للأمام** — لا تُعِد كتابة تاريخ مشترك |
| `InconsistentMigrationHistory` بعد إضافة نموذج مستخدم مخصّص | رحّلت قبل ضبط `AUTH_USER_MODEL` |

### أشهر كارثة: `InconsistentMigrationHistory`

إن شغّلت `migrate` **قبل** ضبط `AUTH_USER_MODEL`، يكون Django قد أنشأ جداول `auth.User` الافتراضية ويرفض التبديل بعدها.

```bash
docker volume rm <project>_dev-db-data
```

في بيئة التطوير: احذف الحجم وابدأ من جديد. في الإنتاج: ترحيل بيانات متعدّد الخطوات لا يستمتع به أحد.

**ولهذا يُنجَز نموذج المستخدم المخصّص في اليوم الأول.** راجع [[نموذج المستخدم المخصّص]].

## 🚀 في الإنتاج

سكربت `run.sh` يُشغّل `migrate` عند كل إقلاع للحاوية، فيُطبّق كل إصدار تغييرات مخطّطه بنفسه.

> [!CAUTION] التراجع عن الكود لا يُرجِع المخطّط
> إن تضمّن نشرٌ ترحيلًا مُدمّرًا (حذف عمود، إعادة تسمية حقل)، فإن `git checkout` يتركك بمخطّط لا يفهمه الكود القديم.
>
> لأي شيء يهمّ، اعمل بالإضافة: أضِف عمودًا يقبل الفراغ، عبّئه، ثم احذف القديم في **إصدار لاحق**.

> [!WARNING] عدّة حاويات تتسابق على الترحيل
> مع حاوية واحدة لا مشكلة. لحظة أن تُوسّع إلى عدّة حاويات تطبيق، ستتسابق على `migrate`. عندها انقل الترحيل إلى خطوة إصدار منفصلة تعمل مرة واحدة.
