## 🥇 A01 — تفويض معطوب على مستوى الكائن

**الثغرة رقم ١ في الـ APIs، كل عام.** تُعرَف بـ IDOR: غيّر المُعرِّف في المسار، تحصل على بيانات غيرك.

```http
GET /api/recipe/recipes/1/     ← وصفتك
GET /api/recipe/recipes/2/     ← …وتُعيد بيانات أيضًا؟
```

```python
# ❌ أي مستخدم مُصادَق يقرأ أي وصفة
class RecipeViewSet(viewsets.ModelViewSet):
    queryset = Recipe.objects.all()
    permission_classes = [IsAuthenticated]

# ✅ الصفّ ببساطة غير موجود بالنسبة لك
    def get_queryset(self):
        return self.queryset.filter(user=self.request.user)
```

- [ ] كل ViewSet لبيانات مملوكة يتجاوز `get_queryset()`
- [ ] اختبار `test_x_limited_to_user` موجود لكل مورد مملوك
- [ ] تحقّقت **يدويًا** أن المستخدم «ب» يحصل على `404` على كائن «أ»

> [!CAUTION] `IsAuthenticated` ليست تفويضًا
> تُثبت أن الطالب **مستخدمٌ ما**، ولا تقول شيئًا عن كونه **المستخدم المعنيّ**. هذا التمييز هو A01 كاملة. راجع [[5.الصلاحيات المخصّصة]].

## 🔑 A02 — مصادقة معطوبة

- [ ] التوكنات تنتهي صلاحيتها — راجع [[مصادقة التوكن]]
- [ ] `/api/user/token/` محدود المعدّل بإحكام — راجع [[2.تحديد المعدّل]]
- [ ] مُتحقِّقات كلمة المرور مفعّلة:

```python
AUTH_PASSWORD_VALIDATORS = [
    {"NAME": "django.contrib.auth.password_validation.UserAttributeSimilarityValidator"},
    {"NAME": "django.contrib.auth.password_validation.MinimumLengthValidator",
     "OPTIONS": {"min_length": 10}},
    {"NAME": "django.contrib.auth.password_validation.CommonPasswordValidator"},
    {"NAME": "django.contrib.auth.password_validation.NumericPasswordValidator"},
]
```

- [ ] رسائل خطأ الدخول **عامّة**: `"Unable to log in with provided credentials."` — لا `"No user with that email"`، فتلك أداة مجانية لعدّ الحسابات
- [ ] كلمات المرور مُجزّأة عبر `set_password`، ولا تُسجَّل أبدًا

## 📤 A03 — كشف مفرط للبيانات

المُسلسِلات هي **حدود خروج بياناتك**.

```python
# ❌ يُسلّم تجزئة كلمة المرور و is_superuser وكل عمود ستضيفه لاحقًا
class Meta:
    model = get_user_model()
    fields = "__all__"

# ✅ قائمة سماح صريحة
class Meta:
    model = get_user_model()
    fields = ["id", "email", "name"]
    extra_kwargs = {"password": {"write_only": True, "min_length": 10}}
```

- [ ] لا مُسلسِل يستخدم `fields = "__all__"`
- [ ] `password` مضبوط `write_only`
- [ ] الرايات الداخلية (`is_staff`، `is_superuser`) غير مكشوفة وغير قابلة للكتابة
- [ ] استجابات الأخطاء لا تُسرّب آثار التتبّع (`DEBUG=False`)

## 📈 A04 — استهلاك موارد بلا قيود

- [ ] تقسيم على كل نقطة نهاية قائمة — [[1.التقسيم إلى صفحات]]
- [ ] `max_page_size` مضبوط، فلا يُستخدم `?page_size=999999` ضدّك
- [ ] تحديد معدّل على الزوّار المجهولين والمُصادَقين
- [ ] `DATA_UPLOAD_MAX_MEMORY_SIZE` و`client_max_body_size` في nginx محدودان
- [ ] رفع الصور يُتحقَّق من نوعه **وأبعاده**، لا من حجمه فقط

> [!WARNING] قنابل الصور
> ملف PNG بحجم ٢٠ كيلوبايت قد يتمدّد إلى غيغابايتات داخل Pillow. تحقّق من الأبعاد قبل المعالجة:
> ```python
> if img.width * img.height > 50_000_000:
>     raise ValidationError("Image dimensions too large.")
> ```

## 📥 A06 — الإسناد الجماعي

```json
{"email": "a@b.com", "password": "x", "is_staff": true}
```

إن كان `is_staff` ضمن `fields`، فهذا الطلب صنع مسؤولًا للتوّ.

- [ ] `fields` تسرد ما يجوز للعميل كتابته فقط
- [ ] `read_only_fields` تغطّي `id` والطوابع الزمنية والملكيّة
- [ ] `user` يُضبَط من `request.user` في الخادم، لا من الحمولة:

```python
def perform_create(self, serializer):
    serializer.save(user=self.request.user)
```

## ⚙️ A07 — سوء الإعداد

```bash
docker compose -f docker-compose-deploy.yml run --rm app sh -c "python manage.py check --deploy"
```

- [ ] `DEBUG = False`
- [ ] `SECRET_KEY` من البيئة، فريد لكل بيئة
- [ ] `ALLOWED_HOSTS` صريح — **لا `["*"]` أبدًا**
- [ ] `SECURE_SSL_REDIRECT` و`SESSION_COOKIE_SECURE` و`CSRF_COOKIE_SECURE` كلها `True`
- [ ] `SECURE_HSTS_SECONDS` مضبوط (**بعد** التأكّد من عمل HTTPS)
- [ ] `X_FRAME_OPTIONS = "DENY"`
- [ ] `CORS_ALLOW_ALL_ORIGINS = False`
- [ ] الحاويات تعمل بمستخدم غير جذر
- [ ] منفذ قاعدة البيانات غير منشور على الإنترنت

## 💉 A08 — الحقن

الـ ORM يُمرِّر المعاملات منفصلة، فأنت آمن **ما لم تنسحب من ذلك**:

```python
# ❌ حقن SQL
Recipe.objects.raw(f"SELECT * FROM core_recipe WHERE title = '{title}'")

# ✅ مُمَرَّر كمعامل
Recipe.objects.raw("SELECT * FROM core_recipe WHERE title = %s", [title])

# ✅ الأفضل: لا تستخدم raw
Recipe.objects.filter(title=title)
```

> [!CAUTION] `%s` هنا ليست تنسيق نصوص
> `cursor.execute("… WHERE id = %s", [x])` تُمرِّر `x` إلى المُشغّل كمعامل.
> `cursor.execute("… WHERE id = %s" % x)` تُدرجها في الـ SQL أولًا.
> الفرق حرف واحد، والخصائص الأمنية مختلفة تمامًا.

- [ ] لا f-strings داخل `raw()` أو `extra()` أو `RawSQL`
- [ ] لا `eval` ولا `pickle.loads` على شيء أرسله العميل
- [ ] مسارات الملفات المبنية من مُدخَل المستخدم مُعقَّمة — `../../etc/passwd` هجوم رفع حقيقي

## 🔄 A10 — استهلاك غير آمن لواجهات الطرف الثالث

- [ ] كل استدعاء HTTP صادر له مهلة — `requests.get(url, timeout=5)`. بدونها يُعلّق مُخدِّم بطيء عاملك إلى ما لا نهاية.
- [ ] استجابات الطرف الثالث يُتحقَّق منها قبل استخدامها
- [ ] حمولات الـ webhook تُتحقَّق توقيعاتها قبل التصرّف بناءً عليها
- [ ] الاستدعاءات الخارجية تحدث في [[9.المهامّ الخلفية مع Celery|مهمّة خلفية]]، لا داخل الطلب

## 🎯 إن لم تفعل إلّا خمسة أشياء

1. `get_queryset()` يُرشِّح حسب `request.user` في **كل** مورد مملوك
2. `DEBUG=False`، و`SECRET_KEY` من البيئة، و`ALLOWED_HOSTS` صريح
3. تحديد معدّل على نقطة تسجيل الدخول
4. لا `fields = "__all__"` إطلاقًا
5. HTTPS مع رايات الكوكيز الآمنة

هذه تُغطّي الغالبية العظمى ممّا يُستغَلّ فعلًا في الـ APIs الصغيرة.
