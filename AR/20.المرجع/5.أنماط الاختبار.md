# 🧪 أنماط الاختبار

> 🇬🇧 النسخة الإنجليزية: [[EN/20.Reference/5.Testing Patterns|Testing Patterns]]

---

## 🏗️ أيّ صنف أساس؟

| الصنف | قاعدة بيانات | استخدمه لـ |
| --- | --- | --- |
| `SimpleTestCase` | ❌ لا شيء | دوال خالصة، `wait_for_db` مع محاكاة |
| `TestCase` | ✅ يُتراجَع عنها لكل اختبار | **الافتراضي** |
| `TransactionTestCase` | ✅ تُفرَّغ لكل اختبار | اختبار `on_commit` والسلوك الحقيقي للمعاملات |
| `APITestCase` | ✅ | مثل `TestCase` + `self.client` هو `APIClient` |

## 📐 بنية الملفات

```text
app/
├── core/
│   └── tests/
│       ├── __init__.py
│       ├── test_models.py
│       └── test_commands.py
└── recipe/
    └── tests/
        ├── __init__.py
        └── test_recipe_api.py
```

> [!WARNING] ملف `__init__.py` الذي ينساه الجميع
> بدونه لا يكون `tests/` حزمة، ولا يجد مُشغّل الاختبارات شيئًا. يُبلّغ عن «Ran 0 tests» ويخرج بحالة **نجاح** — بناء أخضر لم يختبر شيئًا إطلاقًا.

## 🎭 نمط العام والخاصّ

```python
class PublicRecipeApiTests(TestCase):
    """طلبات غير مُصادَقة."""

    def setUp(self):
        self.client = APIClient()

    def test_auth_required(self):
        res = self.client.get(RECIPES_URL)
        self.assertEqual(res.status_code, status.HTTP_401_UNAUTHORIZED)


class PrivateRecipeApiTests(TestCase):
    """طلبات مُصادَقة."""

    def setUp(self):
        self.client = APIClient()
        self.user = create_user()
        self.client.force_authenticate(self.user)
```

## 🏭 دوال المساعدة

ضعها على مستوى الوحدة، فوق أصناف الاختبار:

```python
def create_user(**params):
    defaults = {"email": "user@example.com", "password": "testpass123"}
    defaults.update(params)
    return get_user_model().objects.create_user(**defaults)


def create_recipe(user, **params):
    defaults = {
        "title": "عنوان تجريبي",
        "time_minutes": 22,
        "price": Decimal("5.25"),
    }
    defaults.update(params)
    return Recipe.objects.create(user=user, **defaults)


def detail_url(recipe_id):
    return reverse("recipe:recipe-detail", args=[recipe_id])
```

نمط `defaults.update(params)` يجعل كل اختبار يتجاوز ما يهمّه فقط:

```python
recipe = create_recipe(user=self.user, price=Decimal("2.50"))
```

## 🌐 `APIClient`

```python
self.client.get(URL, {"tags": "1,2"})                    # معاملات استعلام
```

## 🔄 `refresh_from_db()`

```python
res = self.client.patch(detail_url(recipe.id), {"title": "جديد"})

recipe.refresh_from_db()                       # ← بدونها يبقى "قديم"
self.assertEqual(recipe.title, "جديد")
```

كائنك لقطة من الصفّ وقت جلبه. الطلب غيّر **الصفّ**.

## 🎩 المحاكاة — Mocking

```python
from unittest.mock import patch


@patch("core.management.commands.wait_for_db.Command.check")
def test_wait_for_db_delay(self, patched_check):
    patched_check.side_effect = [Psycopg2Error] * 2 + [OperationalError] * 3 + [True]

    call_command("wait_for_db")

    self.assertEqual(patched_check.call_count, 6)
```

| | المعنى |
| --- | --- |
| `return_value` | ما تُعيده المحاكاة في كل مرة |
| `side_effect = [a, b, c]` | تُعيد `a` ثم `b` ثم `c` |
| `side_effect = Exception` | ترفع استثناءً |
| `call_count` | كم مرة استُدعيت |
| `assert_called_with(...)` | استُدعيت بهذه المعاملات **آخر مرة** |

> [!TIP] رقّع مكان **الاستخدام** لا مكان **التعريف**
> ```python
> @patch("core.utils.send_email")     # ❌ recipe.views استورد الاسم مسبقًا
> @patch("recipe.views.send_email")   # ✅
> ```
> هذا أشهر خطأ في المحاكاة. يبدو الترقيع ناجحًا وهو بلا أثر إطلاقًا.

## 🖼️ اختبار رفع الملفات

```python
def tearDown(self):
    self.recipe.image.delete()          # ← لا تُلوّث نظام الملفات

def test_upload_image(self):
    url = image_upload_url(self.recipe.id)

    with tempfile.NamedTemporaryFile(suffix=".jpg") as image_file:
        img = Image.new("RGB", (10, 10))
        img.save(image_file, format="JPEG")
        image_file.seek(0)                            # ← أعِد المؤشّر للبداية
        res = self.client.post(url, {"image": image_file}, format="multipart")

    self.assertEqual(res.status_code, status.HTTP_200_OK)
```

نقطتان يُغفلهما الناس: `seek(0)` — لأن مؤشّر الملف في النهاية بعد الكتابة — و`tearDown` — وإلّا تراكمت صور الاختبار في `MEDIA_ROOT` إلى الأبد.

## 🏃 التشغيل

```bash
docker compose run --rm app sh -c "python manage.py test"
```

```bash
docker compose run --rm app sh -c "python manage.py test --shuffle"
```

| الراية | الأثر |
| --- | --- |
| `--shuffle` | ترتيب عشوائي — **يكشف الاختبارات المتعلّقة ببعضها** |
| `--keepdb` | يُعيد استخدام قاعدة الاختبار؛ أسرع بكثير |
| `--failfast` | يتوقّف عند أول فشل |
| `--parallel` | يوزّع على الأنوية |

## 🎯 ماذا تختبر؟

| دائمًا | نادرًا |
| --- | --- |
| رفض الطلب غير المُصادَق | الـ ORM نفسه |
| أن المستخدم «أ» لا يرى/يُعدّل بيانات «ب» | الـ getters والـ setters |
| رفض المُدخَلات الخاطئة | تفاصيل مكتبات الطرف الثالث |
| المسار السعيد يُعيد الشكل الصحيح | كل تباديل الحقل الواحد |
| عدد الاستعلامات في نقاط نهاية القوائم | |

**اختبارات الصلاحيات هي الأجدر بالكتابة والأكثر إهمالًا.**

## ⚠️ أخطاء شائعة

- **«Ran 0 tests»** ← ينقص `tests/__init__.py`، أو الأسماء ليست `test_*.py`.
- **ينجح منفردًا ويفشل ضمن المجموعة** ← حالة مشتركة. `--shuffle` يُثبتها.
- **التأكيد يرى القيمة القديمة** ← ينقص `refresh_from_db()`.
- **ترتيب القائمة مختلف** ← على الاختبار والعرض استخدام `order_by()` نفسه.
- **المحاكاة بلا أثر** ← رقّعت مكان التعريف.
- **`on_commit` لا يعمل** ← `TestCase` يتراجع. استخدم `captureOnCommitCallbacks(execute=True)`.
