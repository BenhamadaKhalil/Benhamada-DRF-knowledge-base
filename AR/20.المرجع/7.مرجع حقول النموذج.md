# 🗃️ مرجع حقول النموذج

> صنف واحد = جدول. حقل واحد = عمود. كل ما تحت هو اختيار نوع العمود وقواعده.
>
> 🇬🇧 النسخة الإنجليزية: [[EN/20.Reference/7.Model Field Reference|Model Field Reference]]

---

## 🔤 النصّ

| الحقل | العمود | ملاحظات |
| --- | --- | --- |
| `CharField(max_length=n)` | `varchar(n)` | `max_length` **إلزامي** |
| `TextField()` | `text` | بلا حدّ |
| `SlugField()` | `varchar` | مُفهرَس افتراضيًا |
| `EmailField()` | `varchar(254)` | تحقّق من الصيغة |
| `URLField()` | `varchar(200)` | تحقّق من الصيغة |
| `UUIDField()` | `uuid` | ممتاز كمفتاح عامّ |

> [!TIP] `CharField` أم `TextField`؟
> إن كان هناك حدّ طبيعي (عنوان، اسم) فـ `CharField` — القيد توثيقٌ تفرضه قاعدة البيانات. إن لم يكن (نصّ، وصف) فـ `TextField`. في PostgreSQL لا فرق في الأداء بينهما.

## 🔢 الأرقام

| الحقل | العمود | ملاحظات |
| --- | --- | --- |
| `IntegerField()` | `integer` | ±٢٫١ مليار |
| `BigIntegerField()` | `bigint` | |
| `PositiveIntegerField()` | `integer` + قيد | ≥ ٠ |
| `FloatField()` | `double precision` | ❌ **ليس للمال أبدًا** |
| `DecimalField(max_digits, decimal_places)` | `numeric` | ✅ للمال |

## 📅 التواريخ

```python
created_at = models.DateTimeField(auto_now_add=True)   # يُضبَط مرة، عند الإدراج
updated_at = models.DateTimeField(auto_now=True)       # يُضبَط عند كل save()
```

| | `auto_now_add` | `auto_now` |
| --- | --- | --- |
| عند الإنشاء | ✅ | ✅ |
| عند التحديث | ❌ | ✅ |
| قابل للتحرير | ❌ | ❌ |

> [!WARNING] `auto_now` لا يعمل مع `QuerySet.update()`
> `Recipe.objects.filter(...).update(price=5)` يتجاوز `save()`، فيبقى `updated_at` قديمًا.

## ✅ المنطقية والخيارات

```python
class Recipe(models.Model):

    class Difficulty(models.TextChoices):
        EASY = "EA", "سهل"
        MEDIUM = "ME", "متوسّط"
        HARD = "HA", "صعب"

    difficulty = models.CharField(
        max_length=2,
        choices=Difficulty.choices,
        default=Difficulty.EASY,
    )
```

`TextChoices` يمنحك `Recipe.Difficulty.EASY` بدل نصّ سحري، و`recipe.get_difficulty_display()` تُعيد التسمية المعروضة مجانًا.

## 📎 الملفات

```python
def recipe_image_file_path(instance, filename):
    """يُولّد مسارًا فريدًا لصورة وصفة جديدة."""
    ext = os.path.splitext(filename)[1]
    filename = f"{uuid.uuid4()}{ext}"
    return os.path.join("uploads", "recipe", filename)


image = models.ImageField(null=True, upload_to=recipe_image_file_path)
```

الـ UUID ليس تفصيلًا: مستخدمان يرفعان `photo.jpg` سيتصادمان، واسم الملف القادم من العميل **مُدخَل غير موثوق** — يمنع أيضًا هجوم اجتياز المسارات عبر `../../`.

## 🔗 العلاقات

| الحقل | العلاقة | العمود |
| --- | --- | --- |
| `ForeignKey(To, on_delete=…)` | كثير ← واحد | `to_id` على هذا الجدول |
| `OneToOneField(To, on_delete=…)` | واحد ← واحد | `to_id` + فريد |
| `ManyToManyField(To)` | كثير ↔ كثير | جدول وصل مستقلّ |

### `on_delete`

| القيمة | عند حذف الأب | يُنفّذه |
| --- | --- | --- |
| `CASCADE` | احذف هذا الصفّ | Django (بايثون) |
| `PROTECT` | **ارفض** حذف الأب | Django |
| `SET_NULL` | اضبطه `NULL` (يتطلّب `null=True`) | Django |
| `RESTRICT` | ارفض، إلّا إن أزاله cascade آخر | Django |
| `DO_NOTHING` | اترك مفتاحًا معلّقًا | لا أحد |
| `DB_CASCADE` ✨ | احذف هذا الصفّ | **قاعدة البيانات** |
| `DB_SET_NULL` ✨ | اضبطه `NULL` | **قاعدة البيانات** |

> [!CAUTION] `DB_*` جديدة في 6.1 ولا تُطلق الإشارات
> أسرع بكثير عند الحذف الضخم، لكن لا `pre_delete` ولا `post_delete`.
> في هذا المشروع تُحذَف صور الوصفات عبر `post_delete` — فتحويل ذلك المفتاح إلى `DB_CASCADE` يترك **كل الصور يتيمة على القرص**.

### `related_name`

```python
user = models.ForeignKey(User, on_delete=models.CASCADE, related_name="recipes")
```

```python
user.recipes.all()          # ✅ مع related_name
user.recipe_set.all()       # بدونها
```

اضبطه. الاسم الافتراضي يُقرأ بشكل سيّئ، وينكسر تمامًا حين يكون لديك مفتاحان أجنبيان لنفس النموذج.

## ⚙️ خيارات الحقول

| الخيار | المستوى | المعنى |
| --- | --- | --- |
| `null=True` | **قاعدة البيانات** | العمود يقبل `NULL` |
| `blank=True` | **التحقّق** | النماذج والمُسلسِلات تقبل الفراغ |
| `unique=True` | قاعدة البيانات | قيد تفرّد + فهرس |
| `db_index=True` | قاعدة البيانات | فهرس عادي |
| `default=…` | الاثنان | القيمة عند الغياب |
| `help_text` | العرض | يظهر في لوحة الإدارة و OpenAPI |

| نوع الحقل | التركيبة الصحيحة |
| --- | --- |
| نصّ اختياري | `blank=True` **فقط** |
| رقم/تاريخ/مفتاح أجنبي اختياري | `null=True, blank=True` |
| إلزامي | لا هذا ولا ذاك |

> [!WARNING] `null=True` على `CharField` خطأ في الغالب
> ينتج تمثيلان للفراغ — `""` و`NULL` — وكل استعلام صار عليه التعامل معهما. توثيق Django نفسه ينصح بتجنّبه.

## 🏷️ `Meta`

```python
class Meta:
    ordering = ["-id"]
    indexes = [models.Index(fields=["user", "-id"])]
    constraints = [
        models.UniqueConstraint(fields=["user", "title"], name="unique_title_per_user"),
        models.CheckConstraint(condition=models.Q(price__gte=0), name="price_non_negative"),
    ]
```

> [!TIP] القيود تتفوّق على التحقّق
> يمكن تجاوز تحقّق المُسلسِل — من لوحة الإدارة، أو أمر إداري، أو جلسة shell، أو خطأ برمجي. أمّا `CheckConstraint` فتفرضه PostgreSQL على كل كتابة، دائمًا.
> استخدم الاثنين: المُسلسِل يُعطي `400` مفهومة، والقيد يضمن الصحّة.

**ملاحظة:** المعامل صار اسمه `condition` بعد أن كان `check`. الدروس القديمة تستخدم الاسم المهجور.

## 🧬 نماذج هذا المشروع

```python
class Recipe(models.Model):
    user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    title = models.CharField(max_length=255)
    description = models.TextField(blank=True)
    time_minutes = models.IntegerField()
    price = models.DecimalField(max_digits=5, decimal_places=2)
    link = models.CharField(max_length=255, blank=True)
    image = models.ImageField(null=True, upload_to=recipe_image_file_path)
    tags = models.ManyToManyField("Tag")
    ingredients = models.ManyToManyField("Ingredient")

    def __str__(self):
        return self.title
```
